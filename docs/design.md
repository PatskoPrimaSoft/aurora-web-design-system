# Дизайн-правила Aurora

[Начало](../README.md) · [Подключение к приложению](usage.md) · [Имена токенов](tokens.md)

Aurora — платформа GPS-мониторинга коммерческого автопарка: объекты, водители, датчики, геозоны, маршруты, рейсы, отчёты, эко-вождение, видео, уведомления. Интерфейс плотный, про данные, для десктопа; ближе к пульту диспетчера, чем к потребительскому приложению. Оператор держит карту открытой весь день — рисуйте экран, на который смотрят восемь часов подряд.

| Поверхность | Кто | Форма |
|---|---|---|
| **Мониторинг** (user-portal) | операторы, диспетчеры | шапка, левая панель объектов, карта во всю ширину, вкладки функций |
| **Администрирование** (admin-portal) | интеграторы, поддержка, реселлеры | та же шапка, затем одна большая таблица с фильтрами на сущность |

Продукт — Angular 19, карты OpenLayers, графики ECharts, 23 локали. Эталонные экраны — карточки `Monitoring`, `Admin` и пустая оболочка `AppShell`: прочитайте нужную перед тем, как строить экран. Копируемых шаблонов нет — берите раскладку с эталона и стройте экран под задачу.

## Четыре правила, по которым экран принимают

1. **Три скоупа на корне:** `<body data-ds-theme="DEFAULT" data-ds-appearance="light" data-ds-density="cozy">`. В продовом Angular тема по-прежнему ставится классом `theme-RED2` из `FRONT_BRAND`.
2. **Цвет — только токенами, размер — только в px.** Литеральный hex или `rem` в компоненте — провал ревью.
3. **Иерархия — 1px `ds-border` на скруглённой поверхности**; тень только у того, что парит. Иконки — Material Symbols через `DsIcon`. Без градиентов и эмодзи.
4. **Четыре рендера — критерий приёмки:** DEFAULT / light / cozy, DEFAULT / dark / compact, RED2 / light / cozy, RED2 / dark / compact для каждого экрана, диалога и карточки; экран готов, только когда держится в обеих темах, обоих режимах и обеих плотностях.

## Язык и тексты

Тексты живут в `en.json` / `ru.json`, их пишут разработчики, вычитывает поддержка, в остальные 21 локаль они уходят через Crowdin. Голос определяет этот конвейер, а не стайлгайд.

**Строки компонентов** — не в компонентах: `useDsStrings()` берёт их из словаря, по умолчанию `dsStringsRu`. Приложение ставит язык одним провайдером у корня — `<DsStringsProvider strings={dsStringsEn}>` или частичным словарём поверх русского; явный проп (`label`, `actionLabel`, …) побеждает словарь. Источник для Crowdin — `dsStringsEn`.

| Правило | |
|---|---|
| **Регистр речи** | Коротко, буквально, для оператора. Самое короткое верное существительное или глагол в повелительном. Никакого маркетинга. |
| **Заглавные** | Как в предложении везде: `Add object`, `Move to archive`, `Show / hide invalid data`. Никогда Title Case; ВЕРХНИЙ РЕГИСТР — только словесный знак логотипа и метка полосы эко-вождения `THE BEST`. |
| **Лицо** | Безлично. Голый императив для действий (`Save`, `Generate`, `Clear map`), голое утверждение для состояний (`Driver is not assigned`, `Data not available`). «You» — только чтобы объяснить право доступа: `You are not allowed to edit eco-driving parameters.` |
| **Подтверждения** | Вопрос с объектом в типографских кавычках: `Assign “{{driverName}}” to “{{unitName}}”?` Разрушительное действие называет последствие фактом, а не требует смелости. |
| **Ошибки** | Называют правило, а не виноватого: `Can not be empty`, `Not valid`, `No data`. Подстановки — `{{amount}}`, `{{entity}}`, `{{value}}`. |
| **Единицы** | Отдельно от чисел (`km/h`, `кг`, `сек`, `км`), выводятся как `suffix` поля — никогда не вшиваются в подпись. |
| **Пунктуация** | Без точки в подписях, кнопках, заголовках таблиц, коротких подсказках; полные предложения в баннерах и диалогах — с точкой. `/` с пробелами для «или-или». Многоточие редко. |
| **Длина** | Жёсткое правило раскладки: `Save` → `Сохранить` → `Speichern`. Никогда не рисуйте кнопку впритык к английской строке. |
| **Эмодзи** | Нигде — ни в тексте, ни в UI. Статус — это иконка плюс цвет. |

**Словарь предметной области закреплён и слегка необычен — пользуйтесь им.**

| Говорите | Не |
|---|---|
| **object** (`Add object`, `Selected objects`) | vehicle, asset — хотя в коде это `unit` |
| **Generate** (`action.build`) | Build, Create, Run |
| **Move to archive** / **Restore** | Delete |
| **geofence**, **retranslator**, **template set**, **run**, **trip**, **eco-driving**, **violation**, **sensor**, **mechanism**, **norm consumption** | любые синонимы |

**Язык карточки следует её задаче.** Карточка-спецификация — то, по чему потребитель строит, — пишется по-английски, как имена токенов и компонентов, которые она описывает. Карточка-решение, которая существует, чтобы никто не открывал заново закрытый спор, пишется по-русски: её читатель — внутренняя команда. Новую карточку пишите на языке её назначения; не переводите одну под другую.

**Языки в репозитории:** заголовки коммитов — английский; проза в `docs/` и комментарии в коде — русский; пользовательские строки — английский исходник и вручную поддерживаемый русский, остальное синхронизируется машиной. Сдаваемые материалы часто двуязычные.

## Визуальные основы

### Три скоупа

| атрибут | значения |
|---|---|
| `data-ds-theme` | `DEFAULT` · `RED2` — по блоку на реального арендатора: добавляется, а не выбирается |
| `data-ds-appearance` | `light` · `dark` |
| `data-ds-density` | `cozy` · `compact` |

Все три независимы и наследуются, поэтому любое поддерево может их переопределить — компактная таблица внутри cozy-страницы — это один атрибут. Белая метка — ограничение первого класса: тема и логотип арендатора выбираются в рантайме контейнера через `FRONT_BRAND`, не при сборке. Две палитры, `DEFAULT` и `RED2`, — бренды, реально работающие в проде, и два крайних случая по контрасту; light/dark и обе плотности — тоже крайние. Новый арендатор получает свою палитру из своих настоящих фирменных цветов; готового набора «на выбор» нет. Карточки [«Цветовые темы»](../components/DsBrandThemes/README.md), [«Подбор цветов темы»](../components/DsBrandPick/README.md), [«Светлый и тёмный режим»](../components/DsAppearance/README.md).

### Цвет

- **Бренд** — три роли на тему: `ds-brand` (заливка), `ds-brand-subtle` (тинт), `ds-brand-border`, плюс `ds-brand-text` для чернил. **Никогда не красьте текст значением заливки.** Бренд-токенов `-hover` / `-active` нет: ховер и нажатие — универсальный оверлей чернилами (`ds-overlay-hover` 10%, `ds-overlay-press` 16%) поверх любой заливки.
- **Акцент** — только для внимания; текст на нём — `ds-accent-on`. Контролы выбора используют бренд, а не акцент. Где акцент сам является меткой, а не фоном под текст — точка непрочитанного, бейдж непрочитанного в списке, — берите `ds-accent-mark` / `ds-accent-mark-on`: форма должна давать 3:1 к поверхности (WCAG 1.4.11), а жёлтый акцент DEFAULT в значении заливки этого не может. В dark метка равна акценту.
- **Счётчик уведомлений в шапке** — сама заливка акцента (`ds-header-badge-bg` → `ds-accent`, чернила `ds-accent-on`), одна и та же на всех полосах, без обводки и внешнего ореола. Число читается за счёт контраста `ds-header-badge-fg` к заливке. **Бейдж окружения** (`DEV`, `LOCAL`) — заливка акцента (`ds-header-env-bg` / `-fg`): это метка арендатора с текстом, а не знак.
- **Нейтрали** — одна холодная рампа из 13 ступеней, `ds-n-0` → `ds-n-950`, плюс альфа-нейтрали `ds-n-a*` / `ds-w-a*`. Экран называет только алиасы — `ds-bg`, `ds-surface`, `ds-fg`, `ds-fg-muted`, `ds-border`, `ds-divider` и их соседей, — **никогда ступень рампы**. Карточка [«Нейтральные цвета»](../components/DsNeutrals/README.md).
- **Статус** — `success` / `warning` / `danger` / `info` (и `neutral`), у каждого `-bg` / `-fg` / `-line` / `-solid`. **Намеренно не зависят от темы:** объект офлайн должен читаться как офлайн в обоих брендах и в dark. Карточка [«Цвета статусов»](../components/DsStatus/README.md).
- **Словарь автопарка** — `ds-state-moving` / `-parked` / `-offline` / `-invalid` / `-alarm` / `-nodata` сводят состояние объекта на палитру статусов; из них `DsStateIcon` и `DsObjectRow` берут чернила глифа, так что цвет состояния живёт в одном месте, а тонированный диск за ним остаётся на тоне статуса. `nodata` нейтрален, как `parked`: их различает глиф, а не ступень серого.
- **Свежесть данных** — `ds-fresh-live` / `-recent` / `-late` / `-none` (как давно пришло последнее сообщение) красит диск строки объекта, чернила — `ds-fresh-on`. Состояние и свежесть — разные факты: стоящий объект может быть совершенно свежим.
- **Иконки карты** — `ds-map-point` (`#2b8cf7`) на `ds-map-ground` (белый): глиф точки в белом диске, её подпись, заливка пинов. **Намеренно не зависят ни от темы, ни от режима:** тайлы карты светлые и в dark, поэтому одно значение на все четыре набора. Остальные стили карты — треки, геозоны, кластеры — живут в `aur-openlayers`.
- **Чекбоксы используют один компонент `DsCheckbox`** и состояния `'unchecked' | 'checked' | 'indeterminate'`. `onChange(nextState)` возвращает новое состояние; частичный выбор при активации становится полным. У радио только `unchecked` и `checked`. Без видимой подписи задаётся `ariaLabel`.
- **Отключённое — это цветовой токен (`ds-fg-disabled`, `ds-surface-disabled`), никогда не прозрачность.**
- **Чернила на заливке — токен:** `ds-on-brand` на брендовой заливке, `ds-on-solid` на любой `*-solid` статуса. Оба переворачиваются в dark, потому что сами заливки там светлеют.

Градиентов нет нигде.

**Контраст.** Текст держит 4,5:1 во всех четырёх наборах, включая `ds-fg-subtle` и `ds-chart-tooltip-muted`; отключённое (`ds-fg-disabled`) WCAG не нормирует. Границы контролов, у которых граница — единственный признак (пустой чекбокс и радио, трек выключенного переключателя), рисуются `ds-border-control` — ≥ 3:1 к `ds-surface`, `ds-bg`, `ds-surface-hover` и `ds-surface-selected`. `ds-border-field` (1,52:1) по решению владельца остаётся у полей и `secondary`-кнопок, где есть второй признак — подпись, плейсхолдер, текст; не делайте его единственным признаком нового элемента. Действие на инверсной поверхности (тост) — `ds-fg-action-on-inverse`, ≥ 4,5:1, всегда с подчёркиванием. Пороги проверяет `lint/test/run.js`.

### Типографика

**Inter Tight** — интерфейс, **JetBrains Mono** — цифры телеметрии.

Задавайте шрифт одной из девяти ролей — каждая ставит шорткат `font` целиком (`font: var(--ds-type-body)`); кегль, вес и интерлиньяж руками не собираются:

| роль | кегль / вес / интерлиньяж | где |
|---|---|---|
| `ds-type-display` | 30 / 600 / 1.2, трекинг `ds-tracking-tight` | единственный заголовок экрана, один на страницу |
| `ds-type-title` | 20 / 600 / 1.2, `ds-tracking-tight` | заголовок панели, модального окна, шапка карточки |
| `ds-type-section` | 16 / 600 / 1.35 | раздел внутри панели или формы; название продукта в шапке |
| `ds-type-body` | 14 / 400 / 1.5 | проза, ячейки таблиц, значения полей — базовый кегль |
| `ds-type-body-strong` | 14 / 500 / 1.5 | опорная ячейка строки, имя объекта, итог; не для выделения внутри абзаца |
| `ds-type-ui` | 13 / 500 / 1.35 | всё, что нажимается: кнопки, табы, чипы, пункты меню, поля ввода |
| `ds-type-caption` | 12 / 400 / 1.35 | подпись под полем, вторая строка ячейки, хинт, пагинация |
| `ds-type-eyebrow` | 11 / 600 / 1.35, `ds-tracking-eyebrow` | заголовок столбца, метка группы; всегда капитель — без неё 11px читается как сломанный body |
| `ds-type-mono` | 13 / 400 / 1.35, JetBrains Mono | только телеметрия: скорость, координаты, IMEI, таймстемпы, ID |

Плотность на кегль не влияет. Копируя `rem` из исходников Angular, умножайте на 10 один раз — порталы ставят `html { font-size: 10px }` — и оставляйте px. Карточка [«Типографика»](../components/DsType/README.md).

**Шрифты поставляются вместе с пакетом.** `dist/styles.css` уже подключает Inter Tight, JetBrains Mono и Material Symbols из локальных файлов. Дополнительные CSS-импорты и ручное копирование шрифтов не нужны; каталог также работает без CDN. Лицензии и пересборка — [assets/fonts/README.md](../assets/fonts/README.md).

### Шапка

**Шапка нейтральная.** Бренд в ней — это плашка логотипа и индикатор активной вкладки, а не залитая полоса. Каждый цвет шапки идёт через алиасы `ds-header-*`, поэтому `data-ds-appearance` перекрашивает её как всё остальное. Арендатор, которому по договору нужен свой цвет наверху, переопределяет `ds-header-*` в своём блоке темы; готовой цветной полосы система не поставляет.

Стоковый знак — белый на прозрачном, поэтому на нейтральном хроме он стоит на квадрате 34px `ds-header-plate`; арендатор с тёмным знаком ставит `ds-header-plate: transparent`.

Вкладки шапки ставят иконку над подписью, а счётчик — на глиф: по горизонтали места меньше всего при 23 локалях. `stack={false}` — для двух-трёх коротких подписей. Выбранная вкладка красит глиф и подпись в `ds-header-tab-fg-active`, чтобы выбор читался раньше индикатора 3px (`ds-header-indicator`); в теме RED2 брендовые чернила почти нейтральны, там выбор несут индикатор и фон ховера. В покое шапка отделяется границей 1px; передайте `scrolled`, как только контент уходит под неё, — она поднимает `ds-shadow-sm`. Карточка `DsAppHeader`.

**Правка токена, содержащего `var()`:** custom property с `var()` подставляется там, где она объявлена, а не где используется, поэтому алиас нужно повторить в каждом скоупе, который переопределяет то, на что он указывает. Алиасы от бренда и акцента (`ds-header-indicator`, `-tab-fg-active`, `-plate`, `-env-*`, `-badge-*`, `ds-surface-selected`, `ds-focus-color`, пара зума графика) поэтому объявлены дважды: на `:root` и на `[data-ds-theme]`. Без второго блока вложенный скоуп темы оставлял цвет корневого арендатора — шапка RED2 рисовала синий индикатор DEFAULT. Добавляете такой алиас — добавляйте оба.

### Форма, границы, тень

Иерархия — **1px `ds-border` на скруглённой поверхности**. Тень — только у того, что действительно парит: диалоги, меню, тосты, FAB (`ds-shadow-xs` … `ds-shadow-lg`; `ds-shadow-map` — поверх карты). Радиусы: контролы 8px (`ds-radius-control`), контейнеры 12px (`ds-radius-container`), диалоги 16px (`ds-radius-dialog`), чипы и бейджи — пилюля (`ds-radius-chip`, `ds-radius-badge`). Соседним панелям разделитель не нужен: в зазоре просвечивает фон страницы. Карточка [«Форма и глубина»](../components/DsShape/README.md).

### Плотность

`data-ds-density` управляет высотой контрола (`ds-control-h`), поля (`ds-field-h`), строки (`ds-row-h`), отступами ячеек (`ds-cell-pad-x` / `-y`), высотой шапки (`ds-header-h`), зазорами (`ds-gap-*`), паддингами (`ds-pad-*`) и размером иконок (`ds-icon-*`). Ни один компонент не зашивает высоту. Строка в cozy — 44px, в compact — 34px. См. [«Плотность интерфейса»](../components/DsDensity/README.md).

### Фон и изображения

Только плоские фоны. **Никаких hero-картинок, фотографий во всю ширину, паттернов, текстур, рисованных иллюстраций и размытия.** Изображения только функциональные: карта OpenLayers, маркеры и точки на карте (`assets/images/`), аватар водителя.

### Состояния

- **Ховер и нажатие на залитом или тонированном контроле** — оверлей **собственными чернилами** контрола поверх его же фона: `ds-overlay-hover` (10%), `ds-overlay-press` (16%). Ни у одного тона нет своих токенов ховера.
- **`secondary` и `ghost` вместо этого сдвигают фон** (`ds-surface-hover` / `ds-surface-active`): оверлей на прозрачном не виден, а ghost обязан совпадать с ховером строки. `DsTabs tone="onHeader"` берёт `ds-header-hover`.
- **Ховер строки** — `ds-surface-hover`; **выбранная** — `ds-surface-selected`.
- **Ничего не масштабируется** — никакой обратной связи нажатия через `transform`.
- **Фокус — это CSS, один механизм.** Сплошная обводка 2 px с отступом 2 px задаётся токенами `ds-focus-color`, `ds-focus-width`, `ds-focus-offset`. Для кнопок и других нажимаемых контролов она появляется по `:focus-visible`; для оболочки поля `[data-ds-field]` — по `:focus-within`, в том числе после клика мышью. Границы `"error"` / `"warning"` сохраняют цвет статуса при фокусе, а обводка остаётся цвета темы. Токены теней `ds-focus-ring` и `ds-focus-ring-danger` сохранены для совместимости, стандартные поля их не используют. **Ни один компонент не отслеживает фокус, чтобы нарисовать кольцо**. Своё `outline: none` не пишется.
- **Загрузка — на уровне кнопки и обязательна в каждом макете.** Внутри таблицы предпочитайте `DsSkeleton` спиннеру: спиннер ничего не говорит оператору о форме данных.

Почему белый оверлей и сдвиг заливки ломаются в dark — карточка [«Наведение и нажатие»](../components/DsHover/README.md).

Правила появления обводки, составные поля и живые примеры клавиатурной навигации —
карточка [«Фокус»](../components/DsFocus/README.md). Отдельные нативные поля и селекты
показывают тот же контур по `:focus`; слайдеры, ссылки и остальные контролы —
по `:focus-visible`. Внутренние input/select/textarea в `[data-ds-field]` не рисуют
дополнительный контур: его уже показывает оболочка.

### Движение

Почти никакого, намеренно. Четыре длительности: `ds-dur-instant` 80ms, `ds-dur-fast` 120ms — все переходы контролов, `ds-dur` 180ms — тень шапки при прокрутке, `ds-dur-slow` 240ms; две кривые: `ds-ease` — для всех переходов, `ds-ease-out` — замедление, компоненты на неё пока не ссылаются. Готовый переход контрола — `ds-transition-control` (фон, граница, цвет и тень за `ds-dur-fast`); своих длительностей не пишите. Анимации — только `ds-spin` и `ds-pulse`. Без отскоков, переходов между страницами, анимаций появления и параллакса. Под `prefers-reduced-motion` все длительности — 0ms, а `ds-transition-control` — `none`.

### Раскладка

- `DsPageLayout` — оболочка обоих порталов: `left` + `children` + `right`.
- Панель объектов — `ds-panel-w` (340px в cozy, 300px в compact); это единственное место, где живёт это число. Стандартная ширина поля — 250px.
- Высота диалога — по контенту; действия справа, «отмена» затем «подтвердить».
- CSS Grid — для форм и сеток метрик, flexbox — для всего остального. Отрицательные отступы запрещены.
- **Переиспользуемые компоненты не задают себе внешних отступов — отступы задаёт родитель.**
- **Пропсы регионов принимают и слоты.** `DsPageLayout` (`header` / `pageHeader` / `left` / `right` / `footer`), `DsPanel` (`actions` / `footer`), `DsAppHeader` (`actions`), `DsPageHeader` (`actions` / `meta` / `tabs`), `DsDialog` (`actions`), `DsBanner` (`actions`), `DsEmptyState` (`action` / `secondary`), `DsTable` (`empty` / `footer`), `DsBulkActionsBar` (`actions`), `DsSelectionBar` (`actions`) и `DsListRow` (`actions` / `badge`) принимают либо React-узел в пропсе, либо дочерний элемент с `slot="<имя>"` (`data-slot` тоже работает). Поэтому экран собирается из статической разметки, а не в коде. Если заданы оба, побеждает пропс; дети без слота — основной регион.
- Брейкпоинты приходят из `ViewBreakpointService` с именами `s` / `m` / `l` / `xl` (`ds-bp-m`, `ds-bp-l`, `ds-bp-xl`); компоненты ветвятся по `size.more('m')`, а не по media-запросам. Ширины контента — `ds-content-max`, `ds-content-max-prose`. Карточки [«Адаптивность и брейкпоинты»](../components/DsBreakpoints/README.md) и `DsBreakpointsDecisions`; последняя хранит решения и долг по брейкпоинтам приложения.

### Графики

Графики продукта — ECharts. Система владеет их внешним видом и ничем больше: библиотека, конвейер данных и поведение тулбокса остаются как есть.

- **Цвет серии не зависит от темы** — `ds-series-1` … `ds-series-8`, одна полоса светлоты, восемь оттенков, одинаковые во всех брендах; меняется только пара light/dark. Оператор запоминает, что скорость — синяя.
- **Цвет серии — не цвет статуса.** Серия кодирует *величину*, статус — *состояние*; поэтому рампы разные.
- **Разрыв телеметрии остаётся разрывом.** `connectNulls` по умолчанию выключен; включает его продуктовый инструмент «Show / hide invalid data» (`ds-chart-nodata` — зона без данных).
- **Заливка доходит до своего нуля.** `area` и `bar` тянут ось значений до 0. Обрезать можно только линию — закрепите `yMin` / `yMax`, когда шкала задана датчиком, а не днём.
- **Оси, сетка, перекрестие, тултип и зум — семантические алиасы** `ds-chart-*`. Никакой зашитой `#808080` линии сетки.
- **У плота нет своего фона** — он лежит на поверхности панели. Линии сетки пунктирные, у оси значений нет линии оси, у оси категорий есть.
- **Анимация выключена.** Экран оператора перерисовывается на каждое входящее сообщение.
- **Никаких пирогов, бубликов, радаров, круговых шкал, 3D и градиентной заливки.** Вопросы автопарка — это сравнение во времени; одно значение против полос — это `DsScoreBar`.
- Заголовки графиков **выровнены влево**, как все заголовки системы; период и число отсчётов — подзаголовок.
- В проде `echartsTheme.js` читает эти токены из DOM и возвращает хромовую половину `EChartsOption`. Вызывайте его заново после смены темы, режима или плотности и делайте `setOption` — никогда не регистрируйте статическую JSON-тему, она не пойдёт за атрибутом.

Карточка [«Цвета и оформление графиков»](../components/DsCharts/README.md).

### Доступность

WCAG AA — заявленный минимум, новый UI проходит AXE: `role="img"` + `aria-label` на каждом глифе статуса, `aria-current="page"` на активной вкладке навигации, обязательный `label` у каждой кнопки-иконки, `role="status"` / `role="alert"` на баннерах по серьёзности, настоящие контуры `:focus-visible`.

### Диалоги и оверлеи

Модальное окно останавливает мир оператора, поэтому тратится только на три задачи:

1. **Подтвердить необратимое или широкое** — архивировать, восстановить, отвязать, отправить команду на устройство, удалить набор шаблонов.
2. **Создать или изменить один объект**, когда оператор должен остаться на карте или списке позади — `Add object`, `Change owner`, `Assign driver`.
3. **Короткая задача по шагам** — импорт, экспорт, генерация набора шаблонов; максимум три шага.

У всего остального есть поверхность получше: осмотр объекта — **панель объекта**, результат действия — **тост**, условие, которое остаётся истинным, — **баннер**, фильтрация — **панель или меню фильтров**, форма длиннее восьми полей или со своими вкладками — **экран** с `DsPageHeader`.

**Анатомия фиксирована** (`DsDialog`): шапка — необязательный глиф `tone`, заголовок, однострочное `description`, кнопка закрытия; тело — единственная прокручиваемая область; подвал — действия. Высота по контенту до `min(90vh,760px)`; больше никто высоту не задаёт. Радиус 16px, `ds-shadow-lg`, подложка `ds-n-a60`.

**Размер — решение, а не подгонка:** `sm` 420 — подтверждение (заголовок + одно предложение, без тела), `md` 560 — форма одного объекта, `lg` 760 — две колонки или степпер, `xl` 960 — таблица или карта внутри. Если и `xl` тесно — задача была экраном.

**Действия.** Справа, порядок чтения «отмена → подтвердить», ровно один основной тон (`danger`, когда подтверждение разрушает). Третье действие — `ghost` слева. Кнопка подтверждения повторяет глагол заголовка — `Move to archive`, `Assign`, `Send command`, — никогда `OK`, `Yes`, `Submit`.

**Текст** — по правилам выше: вопрос как в предложении с объектом в типографских кавычках — `Move object “Volvo FH16” to archive?` — и описание, которое называет последствие фактом, с точкой, плюс что сохранится: `Its history stays available in reports.` Никаких `Are you sure`, никаких `Warning!`.

**Закрытие.** `onClose` даёт полный набор — Escape, клик по подложке, кнопка закрытия — и это вариант по умолчанию. `dismissable={false}` оставляет кнопку, но игнорирует Escape и подложку: для запроса в полёте или набранной работы, которая потеряется. Без `onClose` диалог не закрывается вовсе — для блокирующего состояния системы, никогда для формы.

**Фокус и наложение.** `aria-modal` — это обещание: окно забирает фокус при открытии, держит Tab внутри и возвращает фокус на кнопку-триггер — экраны своих обработчиков не добавляют. Никогда не открывайте два диалога друг на друге: второе решение значит, что первое становится шагом. Меню, селекты и тосты могут открываться поверх диалога; тосты остаются в `DsToastStack` на уровне страницы.

### Сортировка

У каждого списка **всегда есть порядок, и всегда ровно один**: одно поле, одно направление. Два способа его задать, третьего нет.

- **В таблице порядком владеет заголовок колонки** — настоящая `<button>` внутри `<th>`, `aria-sort` на `<th>`, цикл «по возрастанию ⇄ по убыванию». Шага «без сортировки» нет: порядок по умолчанию — тоже сортировка. Один ключ за раз, `sort=desc#name`.
- **Сортируема только колонка, по которой умеет сортировать тот, кто отдаёт строки.** Таблицы администрирования листают на сервере, поэтому клиентская сортировка переставила бы только текущую страницу — это не порядок. Составные ячейки объявляют поле (`sortBy`); вычисляемые колонки, колонки выбора и действий не сортируются, у несортируемого заголовка нет ни иконки, ни курсора, ни ховера.
- **Статус сортируется по шкале серьёзности, а не по алфавиту подписи.**
- **Пустые значения всегда на слабом конце** шкалы, какое бы направление ни было выбрано.
- Смена порядка возвращает на первую страницу, живёт в **URL** рядом с фильтрами и держит строки на месте под `DsSkeleton` во время перезапроса.
- **Без заголовков колонок порядком владеет меню сортировки** — панель объектов, дерево и списки карточек используют `DsFilterMenu type="sort-by"`. Эти списки загружены целиком, поэтому сортировка честно клиентская. **Поле и направление — раздельно:** радиосписок полей плюс одна пара направлений с подписями от поля (`Newest first`, `A → Z`, `Highest first`). Группировка — не сортировка; `Clear` возвращает порядок по умолчанию.
- **Сортировка — не фильтр**: никогда не чип в `DsFilterBar`. Она видна как активный заголовок или как точка на иконке `sort`, пока отличается от умолчания.
- **Некоторые порядки не оператору менять:** иерархия пользователь → группа → объект, датчики в карточке объекта, хронологические строки (направление можно перевернуть, поле — нет), шаги степпера, строки отчёта, чей порядок — часть отчёта.

Порядки по умолчанию для каждой поверхности и таблица по колонкам — карточки [«Сортировка в таблице»](../components/DsSorting/README.md) и [«Сортировка вне таблицы»](../components/DsSortingMenu/README.md).

## Иконки

**Material Symbols Outlined** — самохостится как шрифт (`fonts/MaterialSymbolsOutlined.woff2`) и это единственный иконочный шрифт системы: глиф — текстовое содержимое элемента, а не SVG. В компоненте этот элемент — **`DsIcon`** (`<DsIcon name="delete"/>`), единственный иконочный примитив: он владеет размером по умолчанию, осью `wght`, таблицей оптических поправок и решением `aria-hidden` / `role="img"`.

Размер глифа — всегда токен `ds-icon-*`, никогда литерал: 20px внутри контролов (`ds-icon`), 24px отдельно стоящий (`ds-icon-lg`), 16px для плотных строк и удаления чипа (`ds-icon-sm`), 14px для глифа при тексте 11–12px — стрелка сортировки, бейдж, шеврон хлебных крошек, галочка степпера (`ds-icon-xs`). Все четыре уменьшаются на полступени в compact. Собственные *габариты* компонента — другое, они остаются числовыми пропсами: диск `DsStateIcon` (28), диаметры `DsFab` (40/48/56), размер `DsSpinner`.

Берите глифы из этого словаря, а не подбирайте новые:

| Группа | Глифы |
|---|---|
| Действия | `add` `edit` `delete` `clear` `close` `check` `search` `settings` `refresh` `undo` `autorenew` `print` `share` `build` `open_with` |
| Файлы и данные | `download` `file_upload` `attach_file` `content_paste` `table_chart` `assessment` `event_note` `straighten` `crop_free` |
| Сообщения | `info` `error` `warning` `check_circle` `help` `priority_high` `notifications` |
| Навигация | `arrow_back` `chevron_left` `chevron_right` `expand_more` `unfold_less` `unfold_more` `apps` `exit_to_app` |
| Списки и порядок | `sort` `filter_alt` `filter_list` `label` `bookmark` `account_tree` `format_list_bulleted` `view_list` |
| Карта и парк | `place` `map` `layers` `layers_clear` `navigation` `local_parking` `local_shipping` `speed` `timer` |
| Доступ | `visibility` / `visibility_off` `lock` / `lock_open` `vpn_key` `person_add` `more_vert` |

**Поворот несёт смысл:** `navigation` поворачивается по курсу объекта и показывает направление; `straighten` повёрнут на −45°, чтобы читаться как линия измерения; `priority_high` — на 180°. Карточка `IconsArrows`.

**Единственное законное исключение-вектор** — слой карты: маркеры геозон и точек — настоящие SVG в `assets/images/` плюс два растра (карточки `IconsMapAssets`, `MapTrack`). Никаких эмодзи и Unicode-символов вместо иконок.

## Логотип

Знак — PNG: белая стрелка-навигатор в белом кольце с тремя расходящимися жёлтыми дугами. `assets/logo/AuroraWhite.png` (256×256, прозрачный фон).

- Нарисован белым по тёмному и невидим на белом — **всегда ставьте его на `ds-brand`, `ds-header-plate` или другой тёмный фон.**
- Локап шапки: квадрат 34px `ds-header-plate` со знаком 26px, зазор 8px, затем название продукта интерфейсным шрифтом (`ds-type-section`, чернила `ds-header-fg`). Ниже брейкпоинта `s` название уходит, остаётся плашка.
- Бейдж окружения (`DEV`, `LOCAL`) может стоять в 8px справа от названия на акцентном фоне.
- Знак и название настраиваются под арендатора в рантайме (`customization.logoUrl`, `customization.title`, `FRONT_BRAND`) — **никогда не считайте локап фиксированным**: оставляйте место для более длинного названия и другого знака.

SVG-логотипа, локапа только из словесного знака, монохромной версии и спецификации охранного поля нет. Название набирается интерфейсным шрифтом; старые шрифты словесного знака в систему не входят. Карточки `BrandLogoMark` и `BrandLogoLockup`.

## Чего здесь нет

- **Мобильного приложения.** Android-приложение существует, но его исходников не было, поэтому нет ни мобильного UI-кита, ни мобильных паттернов. Поведение ниже брейкпоинта `l` описано, но не воссоздано.
- **Маркетингового сайта продукта.** В этом репозитории есть локальный каталог и справочник дизайн-системы.
- **Шаблона слайдов.**
- **Копируемых шаблонов экранов.** Источник раскладки — эталонные экраны `Monitoring`, `Admin`, `AppShell`.
- **Стилей картографической библиотеки.** Цвета треков, заливки геозон, кластеризация и легенда погоды живут в `aur-openlayers` — отдельном репозитории, которого здесь нет.
- **Легаси-слоя.** Прежнее воссоздание Angular-интерфейса удалено; [руководство по миграции](migration.md) хранит карту имён, визуала больше нет. Как экран выглядит сегодня — смотрите в запущенном Angular-приложении.
- **Легаси-шрифтов.** Базовый шрифт Material Icons и шрифты словесного знака (Nasalization, MTSText) лежат в репозитории Angular, не здесь.
