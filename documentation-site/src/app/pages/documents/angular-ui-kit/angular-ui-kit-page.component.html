Правила Angular UI kit

ng-ui-kit/README.md · Подключение · Дизайн-правила

UI kit разрабатывается в этом репозитории и поставляется через @primasoftllc/design-system/angular . Приложения устанавливают пакет и импортируют готовые компоненты. Общие токены, состояния и правила применения едины с дизайн-системой; состав и публичный Angular API каждого компонента согласуются отдельно.

Практический порядок работы — добавление компонентов .

Версия и текущая готовность

Библиотека компилируется на Angular 19.2.25 , Node 22, TypeScript 5.8.3. Независимые потребители используют Angular 19.2.25 / CLI 19.2.27 и Angular 20.3.34 / CLI 20.3.40, RxJS 7.8.2 и Zone.js 0.15.1. Поддержка 19.0/19.1 и других major не подразумевается автоматически: для них нужна отдельная проверка совместимости. SSR, hydration и zoneless пока не заявлены.

Peer range — ^19.2.25 || >=20.3.34 : поддержка ветки 19.2 добавлена без удаления прежнего диапазона. Реально проверяются 19.2.25 и 20.3.34, не все будущие major. Версия 5.1.0 была собрана на Angular 20; описанный переход относится к Unreleased.

В текущем публичном Angular-входе экспортируются DsButtonComponent , DsIconComponent , DsFabComponent , сервис темы и директива скоупа; интеграция ECharts подключается отдельно. Для иконки подготовлена страница с примерами, API и токенами; кнопка ещё дорабатывается. Доступные компоненты представлены в каталоге Angular-компонентов . Это не утверждённый перечень будущих компонентов.

Версия приложения должна быть не ниже версии компилятора библиотеки. Матрица Node/TypeScript взята из таблицы Angular , правило компиляции — из руководства по библиотекам . Angular 19 уже вне upstream LTS; здесь он выбран как версия целевого приложения.

Расположение и поставка

  • Реализации: ng-ui-kit/src/components/<name>/ ; публичные экспорты: ng-ui-kit/src/core.ts .
  • Standalone-компоненты с ChangeDetectionStrategy.OnPush , строгими шаблонами и типами.
  • Начиная с Angular 19 компоненты, директивы и pipes standalone по умолчанию; избыточный standalone: true в реализации и примерах не указывать.
  • Библиотека поставляется с partial compilation и сгенерированными декларациями. Потребитель не компилирует исходники из репозитория через tsconfig.paths .
  • Angular остаётся peer dependency. Базовый Angular-вход не импортирует React или ECharts; графики остаются в /angular/echarts . Не добавлять зависимость от приложения.
  • Стили и шрифты подключаются один раз через пакетный styles.css , как в руководстве. Компонентные стили поставляются вместе с компонентом; установка не требует копирования файлов.
  • Текущие публичные имена provideAurora , AuroraThemeService и AuroraScopeDirective сохраняются.

Имена, inputs и outputs

Исходники оформляются читаемо: два пробела, ориентир 100 символов и перенос строк до 120 символов. Нетривиальные шаблоны и стили выносятся в отдельные файлы рядом с .ts ; inline допустим только для небольших фрагментов. HTML сохраняет отступы и иерархию, CSS/SCSS — отдельные строки для свойств. SCSS нового сайта не означает автоматической поддержки SCSS текущим сборщиком библиотеки.

Классы компонентов — Ds<Name>Component , директив — Ds<Name>Directive . Для нативного элемента используется атрибутный селектор с ограничением по тегу: первая кнопка — DsButtonComponent , селектор button[dsButton] . Для составного виджета без подходящего нативного корня — ds-<name> . Не создавать универсальный элемент с ручной имитацией клавиатуры обычной кнопки.

Inputs объявляются через input() . Имена, типы и значения по умолчанию согласуются для конкретного компонента с учётом дизайн-системы и нативного HTML. Булевы атрибуты используют booleanAttribute . Публичные типы и события должны соответствовать Angular и оставаться независимыми от приложения.

Текст и произвольное содержимое передаются через ng-content ; именованные области нужны только при отдельном сценарии. Доступное имя остаётся на интерактивном элементе. Нативные type , name , value , aria-* , data-* и событие (click) сохраняют обычный смысл. Не добавлять output click или дублирующий onClick . Для собственных событий — output<T>() с типизированным значением, без префикса on .

Компоненты ввода значений поддерживают Angular Forms через ControlValueAccessor: значение, touched, disabled и reset проверяются в форме. Для кнопки CVA не нужен. Тексты интерфейса передаёт приложение; внутренние служебные строки должны иметь типизированный способ переопределения до выпуска соответствующего компонента.

Дизайн и поведение

Цвета берутся из семантических токенов, размеры задаются в px, внешние отступы — родителем. Компонент наследует тему, оформление и плотность через CSS-переменные и auroraScope ; не читает глобальную тему для вычисления inline-цветов. Локальный скоуп имеет тот же приоритет, что в эталоне.

Реализуйте применимые состояния: наведение, нажатие, клавиатурный фокус, disabled, loading и ошибки. Видимый фокус, контраст, область нажатия, длинные подписи и reduced motion подчиняются основам системы. DOM-доступ остаётся локальным, обработчики и наблюдатели освобождаются при уничтожении.

Первый компонент: кнопка

Доступна кнопка DsButtonComponent :

Кнопка поддерживает тон, размер, иконки слева и справа, loading, disabled и fullWidth. Подпись передаётся содержимым button; действие обрабатывается нативным click. Для отправки формы задаётся type="submit" ; обычное действие использует type="button" . Загрузка должна защищать от повторных действий, сохранять подпись, размеры и фокус. Недоступное состояние использует нативную блокировку кнопки.

Документация и критерии готовности

Правила применения и типичный пример описываются в README рядом с Angular-компонентом. Публичные типы формируются из Angular-кода; таблицы параметров на новом сайте пока поддерживаются явно. Страница компонента показывает работающие Angular-примеры и ссылается на применимые токены и правила.

Пока Angular API документируется рядом с исходником, а работающие проверочные примеры находятся в независимых Angular consumer-приложениях. Руководство подключения ссылается на документацию компонентов. Эти приложения проверяют поставку пакета и не являются публичным каталогом.

Публичные демонстрации размещаются в documentation-site/ и не входят в библиотеку. Сайт импортирует локально собранную библиотеку через её публичный Angular-вход. npm run dev:site-angular подготавливает зависимости и отслеживает изменения; npm run build:site-angular выполняет production-сборку. Подробности — documentation-site/README.md , направление миграции — docs/plans/angular-ui-kit-vision.md .

Компонент готов к поставке, когда:

  • экспорт и типы доступны из установленного tarball без source aliases;
  • production AOT проходит в целевом Angular 19.2 и в сохраняемом Angular 20 consumer;
  • реальные браузерные тесты проверяют мышь, клавиатуру, фокус, формы и изменения inputs;
  • проверены DEFAULT/light/cozy, DEFAULT/dark/compact, RED2/light/cozy, RED2/dark/compact, ширина 390 px и широкий экран, длинный текст и доступность;
  • пример подключения компилируется, API и ограничения описаны, CHANGELOG обновлён;
  • Полный npm run verify проходит для действующего репозитория без удаления существующих проверок.

Новый компонент переносится после проверки первого полного пути «исходник → пакет → приложение». Отсутствующий токен или общее правило исправляется в дизайн-системе, без отдельной Angular-палитры и расходящихся копий основ.
