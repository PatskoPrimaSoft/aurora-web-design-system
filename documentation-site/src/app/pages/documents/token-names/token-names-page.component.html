На главную

Регламент имён токенов

Имя токена — это публичный контракт системы, наравне с именами компонентов и входных параметров ( политика версий ). Значение токена можно поправить патчем; имя нельзя поправить никогда — только выпустить новое и провести потребителей через алиас. Поэтому имя придумывается один раз и по правилам.

Единого внешнего стандарта тут нет: W3C-группа по токенам стандартизирует формат файла, а не имена. Всё, что ниже, — правила этой системы.

Проверяется машиной: node design-system/lint/scripts/check-names.js (входит в npm test ). Параметры и список долгов — design-system/lint/naming.config.json.

Форма

Только нижний регистр, цифры и дефисы. Каждый сегмент — слово, а не сокращение на вкус автора ( background → bg, foreground → fg, duration → dur — сокращения ниже перечислены и закрыты; новых не заводим).

Имя описывает назначение: ds-brand-text — брендовый текст, ds-surface-hover — поверхность при наведении. Выбирайте роль по задаче, а не по совпадению цвета.

Префикс

Новые токены используют ds-: это переменная дизайн-системы. Прежний префикс v2- относится к истории переименования, а не к версии пакета. Проверка имён пока принимает оба префикса; для новых имён выбирайте ds-.

Два уровня

Примитивы — сырые значения без роли. В системе это только нейтральная рампа ds-n-0 … ds-n-950 и альфа-нейтрали ds-n-a* / ds-w-a*.

Семантика — всё остальное: имя говорит, для чего токен, а не как он выглядит. Экран называет только семантику. background: var(--ds-n-100) — ошибка ревью, даже если цвет верный: ступень рампы не сообщает, что это за поверхность, и при смене темы окажется не тем.

Компонентного уровня в системе нет и заводить его не нужно: роль и домен покрывают всё, что встречалось.

Слоты

Слот — последний сегмент, он говорит, какую часть рисунка красит токен. Набор закрыт:

слот что это
bg фон-подложка, тинт
fg чернила, глиф
line граница, разделитель
solid плотная заливка
on чернила на заливке того же имени ( ds-brand → ds-on-brand )

Статус — всегда четвёрка целиком: success / warning / danger / info, каждый с bg, fg, line, solid. Три слота из четырёх — незакрытая работа, проверка это ловит.

Брендовые роли: ds-brand (заливка), -subtle (тинт), -border, -text (чернила). Заливка никогда не используется как цвет текста.

Ступени размера

Лестница: 3xs < 2xs < xs < sm < md < lg < xl < 2xl < 3xl. Другие слова ( small, xxl, huge ) не заводятся — проверка их не пропустит.

Своя лестница бывает у домена, если она общепринята: брейкпоинты s < m < l < xl, начертания regular < medium < semibold < bold. Такие лестницы объявляются в design-system/lint/naming.config.json, а не подразумеваются.

Безсуффиксное имя означает середину или не существует. ds-gap рядом с ds-gap-md читается как «обычный отступ», и разработчик берёт его именно так — а получает другую ступень. Либо базовое имя равно md, либо его нет.

Домен

Домен — первый сегмент после префикса, когда токен принадлежит месту, а не роли: chart-, header-, state-, fresh-, series-. Домен заводится, когда у места есть собственный словарь из нескольких токенов; ради одного токена домен не создаётся.

Домен — это место или предметная область, а не компонент. ds-row-h — высота строки везде, а не высота строки DsTable.

Что в имя не входит

  • Тема, бренд, светлость, плотность. Это значения токена, а не разные токены. ds-surface в dark другой — имя то же. Токена ds-brand-red2 быть не может.
  • Конкретный цвет. -blue, -red, -yellow в имени семантики запрещены: в другом бренде они станут ложью.
  • Состояние как отдельный токен там, где есть оверлей. Ховер и нажатие — это ds-overlay-hover / -press поверх заливки, а не ds-brand-hover.
  • Имя компонента.

Как заводится новый токен

  1. Сформулировать роль, а не значение: не «нужен серый #8A8F98», а «нужны чернила для подписи под значением».
  2. Проверить, что роли ещё нет. Большинство запросов на новый токен — это запрос на существующий.
  3. Имя по грамматике выше. usage обязателен: одна фраза о том, где токен применяется и на чём лежит.
  4. node design-system/lint/scripts/check-names.js — проверка формы, лестниц, слотов и уникальности имени.
  5. Новый токен — это minor ( политика версий ).

Переименование

Никогда одним релизом. Порядок:

  1. Минор: новое имя становится каноном, старое остаётся алиасом на него и помечается устаревшим. Обе записи задаются в design-system/tokens/source.json; tokens.json генерируется при сборке.
  2. Потребители переезжают. Линтер системы подсказывает новое имя в тексте ошибки, если старое уже снято.
  3. Мажор: алиас снимается, старое имя исчезает, запись в CHANGELOG отдельной строкой на каждое имя.

Долги

Отступления, которые есть сегодня, записаны поимённо в design-system/lint/naming.config.json с причиной. Это не отключённые правила: новый токен мимо грамматики не пройдёт, а старые видны списком и закрываются в ближайший мажор.

В текущем design-system/lint/naming.config.json список долгов пуст. Три устаревших алиаса удалены в 4.0.0 вместе с записями о долгах; aurora/known-token отклоняет старые имена. Замены при обновлении:

устарело используйте почему
ds-gap (12 / 8 px) ds-gap-sm-plus безсуффиксное имя ниже своей -md
ds-pad (12 / 8 px) ds-pad-sm то же; у отступов ступени sm не было
ds-fresh-on ds-fresh-fg чернила без парной заливки

Удаление алиасов — ломающее изменение.

Что остаётся человеку

Машина проверяет форму имени. Она не может проверить, что имя правдиво: что ds-surface-selected действительно про выделенную строку, а не про наведение, и что новый токен не дублирует существующую роль под другим словом. Это работа владельца системы на приёмке.
