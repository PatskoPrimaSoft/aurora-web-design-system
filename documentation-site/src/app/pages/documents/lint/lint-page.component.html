Линтер системы

Пять правил stylelint, которые проверяют то, что нельзя проверить глазами на ревью. Правила живут внутри пакета системы и читают тот же tokens.json, из которого генерируется tokens.css, — поэтому линтер не может разойтись с системой: переименовали токен в мажоре, и у всех потребителей это стало ошибкой сборки, ничего рассылать не нужно.

Чего здесь нет: TypeScript и шаблоны Angular (литералы в конфигах ECharts, inline [style], глубокие импорты) — это отдельный ESLint-слой, он не сделан. Baseline-режима для легаси тоже нет: существующее приложение включает линтер на срезе 1, когда цвета уже переведены на токены.

Правила

known-token

var(--ds-…) должен указывать на токен, который существует в tokens.json. Плюс приложение не имеет права объявлять свои --ds-* — это пространство имён системы.

Второй случай — имя, скопированное со страницы артефакта: её tokens.css называет семейства с префиксом --font-. В приложениях этого имени нет — продуктовая таблица стилей называет их так же, как tokens.json.

Опции: tokensPath — читать список прямо из tokens.json вместо предсобранного; allowDeclare: true — разрешить объявлять --ds-* (нужно только самой системе).

no-literal-color

Любой литеральный цвет в значении: hex, rgb(), hsl(), oklch(), color-mix(), именованные цвета. transparent, currentColor и содержимое url() разрешены. Литерал в фоллбэке var(--ds-fg, #333) тоже ошибка — это обход, а не подстраховка.

Опции: ignoreProperties — список свойств, где литерал допустим (например filter ).

no-rem

Размеры задаются в px: порталы ставят html { font-size: 10px }, поэтому rem из старого кода умножается на 10 один раз и остаётся px.

Опции: units (по умолчанию ["rem"] ), ignoreProperties.

focus-from-tokens

Кольцо фокуса приходит из dist/styles.css. Правило ловит outline, box-shadow и border-color внутри :focus / :focus-visible, если значение не ссылается на токен, а также outline: none где угодно.

shadow-token-only

box-shadow — только ссылка на ступень тени из системы или none. Составное значение var(--ds-shadow-sm), 0 0 0 1px не проходит: вторая тень — это своё кольцо, а оно приходит из токенов фокуса. Список доступных ступеней в тексте ошибки берётся из системы, а не из текста правила.

Опции: tokenPattern — регулярное выражение имени ступени.

Проверка имён токенов

node design-system/lint/scripts/check-names.js — отдельная проверка, не stylelint: она читает tokens.json и сверяет имена с регламентом ( имена токенов ) — форма, лестницы ступеней, четвёрка слотов у статусов, уникальность, чернила без парной заливки, безсуффиксное имя рядом с -md.

Проверяется система, а не приложения: имя токена заводится здесь, здесь и контролируется. Лестницы доменов и список сегодняшних долгов — design-system/lint/naming.config.json; долг записывается с причиной, и новых он не разрешает.

Разработка

design-system/lint/tokens.allowed.json генерируется и руками не правится. Тест падает, если его забыли пересобрать после правки tokens.json, — то же поведение, что у tokens.g.dart в мобильной системе.

Новое правило принимается только с парой строк в design-system/lint/test/run.js: «плохой код — ожидаемая ошибка» и «похожий хороший код — ноль ошибок». Правило без теста тихо перестаёт срабатывать при первом рефакторинге, и никто этого не замечает.

no-deprecated-token

Предупреждает о ссылке на устаревшее имя, пока оно живёт алиасом. Список и версия удаления — aliases в design-system/lint/naming.config.json; сейчас список пуст. В готовом конфиге — severity: warning. Удалённые в 4.0.0 --ds-gap, --ds-pad и --ds-fresh-on отклоняет aurora/known-token; замены описаны в design-system/docs/migration.md.
