Новый компонент разрабатывается в ng-ui-kit/ и поставляется из @primasoftllc/design-system/angular. Этот порядок дополняет правила Angular UI kit . Для подключения библиотеки в приложение используйте руководство подключения .

1. Согласуйте назначение и Angular API

Согласуйте назначение компонента и применимые правила дизайн-системы: состояния, токены и поведение. Зафиксируйте inputs, события, содержимое и доступное имя. Angular API выбирается по задаче и нативной семантике; параметры существующих демонстраций не становятся обязательным контрактом.

Иконка и кнопка в репозитории служат текущей основой и ещё дорабатываются. Если компоненту не хватает общего токена или правила, сначала согласуйте изменение основы дизайн-системы. Отдельную Angular-палитру и копии токенов не добавляйте.

3. Реализуйте состояния и формы

  • Inputs объявляйте через input(), булевы атрибуты — с booleanAttribute. Собственные события — через типизированный output<T>() без префикса on. Нативные события сохраняют обычный смысл: например, (click)="save()". Имя и тип собственного события согласуются в публичном API конкретного компонента.
  • Сохраняйте нативные HTML-атрибуты и события. Не создавайте output click или onClick поверх обычного (click).
  • Используйте семантические CSS-токены, размеры в px и отступы родителя. Тема, оформление и плотность наследуются через переменные и auroraScope.
  • Реализуйте применимые состояния: hover, pressed, focus, disabled, loading, ошибки и длинный текст. Доступное имя остаётся на интерактивном элементе.
  • Для полей значений добавьте ControlValueAccessor и проверьте value, touched, disabled и reset в Angular Forms. Кнопке CVA не нужен.
  • Освобождайте обработчики и наблюдатели при уничтожении компонента.

Базовый вход содержит Angular-компоненты и общие средства библиотеки, без зависимости от приложения. Интеграция ECharts подключается отдельно через /angular/echarts.

5. Добавьте документацию и работающий пример

В README.md рядом с компонентом опишите публичный импорт, imports, типичный шаблон, inputs, события, значения по умолчанию и ограничения. Дайте ссылки на применимые правила дизайн-системы.

Добавьте пример в независимые потребители Angular 19 и 20: ng-ui-kit/tests/consumers/angular-19/ и angular-base/. Он должен импортировать компонент из установленного пакета, а не из репозитория. Включите его в отображаемый Angular-шаблон и проверьте реальное поведение в ng-ui-kit/tests/browser/.

Общие примеры можно хранить в ng-ui-kit/tests/consumers/shared/. Если добавляете новый общий файл, включите его копирование в ng-ui-kit/tools/check-angular.mjs: сейчас список этих файлов задан явно. В этом же инструменте подключаются проверки поведения потребителей; появление нового файла само по себе не добавляет его сценарии в проверку.

Параметры и события документируйте по реализации Angular-компонента и его декларациям типов. Автоматической генерации таблиц Angular API на новом сайте пока нет; описание поддерживается явно. Показанный код должен воспроизводить работающий Angular-пример.

Проверочные примеры потребителей не заменяют публичные демонстрации сайта. Демонстрации добавляются в documentation-site/src/app/ и импортируют компонент из @primasoftllc/design-system/angular, а не из исходников библиотеки. Команды разработки и проверки описаны в documentation-site/README.md. План перехода — docs/plans/angular-ui-kit-vision.md.

6. Проверьте путь от исходника до приложения

Команды запускаются из корня репозитория, Node 22 берётся из mise. Во время разработки используйте целевую проверку:

build готовит библиотеку и пакет в .tmp/package/. check:angular устанавливает tarball без сети в независимые приложения и запускает production AOT и браузерные проверки. До первого запуска подготовьте кеши по ng-ui-kit/README.md#команды. Для локального tarball используйте npm run pack; не копируйте в приложение src/ или .tmp/package/ вручную.

Проверьте четыре режима: DEFAULT/light/cozy, DEFAULT/dark/compact, RED2/light/cozy и RED2/dark/compact. Для каждого важного сценария нужны ширина 390 px и широкий экран, мышь, клавиатура, фокус и доступность. Для изменяемых inputs проверяйте обновление после первого рендера. Для форм — отправку, валидацию и reset, для асинхронных действий — loading и защиту от повторного запуска.
