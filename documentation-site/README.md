# Сайт документации Aurora

Отдельное Angular-приложение, которое постепенно заменит существующий сайт.
Добавлены общая оболочка, отдельные меню дизайн-системы и компонентов, поиск
по названиям и группам меню, настройки демонстраций. По образцу старого сайта
перенесены страницы «Прочитать первым» и «Типографика», включая самостоятельные
примеры HTML/CSS. Остальные темы пока открывают явные заглушки.
React-пример поиска на вводной странице заменён заглушкой до подготовки
Angular-компонентов. Исходники старого сайта сохраняются без изменений.
На время перехода тексты перенесённых страниц допустимо хранить в обеих версиях.
Новые Angular-шаблоны находятся в `src/app/pages/`; старые копии будут удалены
вместе с прежним сайтом. Отдельной системы синхронизации текстов не вводится.
Оглавление формируется по `h2[id]` и `h3[id]` внутри статьи автоматически:
заголовок и стабильный `id` задаются только в шаблоне, отдельного списка нет.
Текущий раздел подсвечивается при прокрутке и переходах по якорям. Обычная
прокрутка не меняет адрес страницы и историю браузера.

В каталоге пока только Icon и Button: у иконки есть минимальная демонстрация и оба режима блока кода,
страница кнопки ожидает доработки. Это не окончательный состав библиотеки.
Полные страницы компонентов с кодом, параметрами и токенами ещё не перенесены.
Настройки в шапке пока используют нативные select; замена их общими компонентами
и сравнение четырёх режимов остаются последующими этапами.

Зависимости и команды находятся в корневом `package.json`.
Все команды выполняются из корня репозитория:

```sh
npm install
npm run dev:site-angular
npm run build:site-angular
```

Разработка: <http://127.0.0.1:4200/>. Angular CLI отслеживает изменения
исходников сайта и обновляет приложение в браузере. Перед запуском автоматически
собираются дизайн-система и Angular UI-kit; в dev-режиме изменения их исходников
также вызывают пересборку и обновление сайта. Ошибки выводятся в терминал;
после исправления исходника наблюдение продолжает работать.
Учитываются также отдельные HTML-шаблоны и SCSS-файлы библиотеки. Изменения
настроек сборщика требуют перезапуска команды; специальные проверки удаления,
переименования ресурсов и аварийного завершения процессов пока не добавлены.

## Страницы и оформление исходников

Каждая перенесённая статья и страница компонента имеет собственный route-компонент:

- `src/app/pages/foundations/overview/` — вводная страница;
- `src/app/pages/foundations/typography/` — типографика;
- `src/app/pages/components/index/` — начальная страница каталога;
- `src/app/pages/components/icon/` и `button/` — отдельные страницы компонентов.

Маршруты перечислены в `src/app/app.routes.ts`. Содержимое страниц не выбирается
общим `switch` или параметром `data`. Новая статья добавляется своим компонентом
и маршрутом. Вложенные адреса также можно добавлять отдельными маршрутами.
Один временный `PendingPageComponent` используется только для ещё не перенесённых
тем; его заголовок берётся из стандартного `title` маршрута. Страница 404 отдельная.

`shared/article-layout/` — общая оболочка статьи: заголовок, проекция содержимого,
автоматическое оглавление и подсветка текущего раздела. Она не импортирует конкретные
страницы и не выбирает их содержимое.

Шаблоны и стили страниц хранятся в отдельных `.html` и `.scss` рядом с `.ts`.
Inline-вариант допустим только для действительно небольшого шаблона или стилей.
SCSS обрабатывает уже установленный Angular-сборщик; стили дизайн-системы остаются
готовым CSS, а сборка самой библиотеки UI-kit этим изменением не переводится на SCSS.
Системные CSS-переменные сохраняются; SCSS не создаёт вторую систему токенов.

Форматирование: два пробела, ориентир 100 символов, переносимые строки не длиннее
120. Правила заданы в локальных `.prettierrc.json` и `.editorconfig`:

```sh
npm run format:site
npm run format:site:check
```

Форматтер работает только в `documentation-site/`; генерируемые файлы игнорируются.
Команды используют Prettier с одним дополнительным правилом для HTML:
первый атрибут остаётся на строке открывающего тега. Закрывающий `>` остаётся
рядом с последним атрибутом. Для сохранения этого правила используется
`tools/format.mjs`, а не прямой запуск Prettier.
Проверка форматирования также включена в `verify`, группу `catalogue`.
Используются явные закрывающие теги Angular-компонентов, чтобы не провоцировать
HTML-инспекции IDE, хотя Angular поддерживает самозакрывающуюся запись.

## Общие блоки содержимого

Три независимых компонента сайта находятся в `src/app/shared/` и не входят в UI-kit:

- `ExampleBlockComponent` (`aurora-example-block`) — проекция содержимого,
  рамка `--ds-border`, радиус `--ds-radius-lg`, внутренний отступ 24 px
  (16 px при ширине до 400 px). `background="surface"` использует `--ds-surface`,
  `background="subtle"` — `--ds-bg`. Цвет текста — `--ds-fg`.
  Внешние отступы и настройки темы задаёт родитель.
- `CodeBlockComponent` (`aurora-code-block`) — обязательная строка `code`,
  `language` (typescript/html/css/scss/json/shell/text), необязательный `fileName`.
  По умолчанию код виден; `collapsible` добавляет собственное раскрытие
  «Показать код» / «Скрыть код». Компонент сам копирует исходную строку;
  при отказе clipboard выделяет код для ручного копирования.
- `DisclosureComponent` (`aurora-disclosure`) — нативные details/summary,
  закрытые по умолчанию. Заголовок проецируется через `slot="title"`, остальное
  содержимое — в тело. Этот компонент не используется внутри CodeBlock.

Отступы кода сохраняются через `pre` и `white-space: pre`, длинные строки
прокручиваются внутри блока. Подсветка использует уже установленный highlight.js,
как в старом каталоге, с ограниченным набором языков. Цвета подсветки взяты
из прежних общих стилей и используют токены. Angular дополнительно очищает
сгенерированный HTML; исходный код не вставляется в шаблон как исполняемая разметка.
Файл `_code-highlighting.scss` ограничивает правила вставленных span-элементов
селектором `aurora-code-block`.

Первое применение — обёртка и два варианта кода на странице Icon, раскрывашка
полного названия в «Типографике». Открытый HTML и раскрываемый TypeScript на
странице Icon временно показывают оба режима общего блока, а не задают окончательную
структуру страницы компонента. Цвет подписи Disclosure соответствует этому месту
«Типографики»; для других статей оформление нужно сверять с оригиналом, а не
автоматически применять синий цвет всюду. Короткие исходники пока передаются строками
со страницы Icon; организация файлов полноценных примеров обсуждается отдельно.

## Локальные результаты и публичные импорты

Обе команды сначала используют существующие сборщики библиотеки, затем Angular CLI.
Старый каталог и React при этом не собираются. Отдельная подготовка доступна
командами `npm run build:design-system` и `npm run build:ui-kit-angular`.

- CSS, токены и JSON: корневой `dist/`.
- Шрифты: корневые `fonts/` и `assets/fonts/`, как в публикуемом пакете.
- Angular-библиотека: `dist/angular/` (partial compilation и типы).

Это генерируемые, игнорируемые Git файлы. Исходники редактируются только
в `design-system/` и `ng-ui-kit/src/`. Очистку выходных папок во время
работы dev-сервера выполнять не следует.

Компоненты импортируются из `@primasoftllc/design-system/angular`, CSS —
из `@primasoftllc/design-system/styles.css`. Поскольку сайт находится внутри
пакета с этим именем, импорты разрешаются через корневой `package.json` и его
`exports` в локальный `dist/`. Нет установки пакета в себя, source aliases
или разных путей для dev и production. Angular CLI связывает partial-код
библиотеки и переносит файлы шрифтов из CSS в результат сборки сайта.

В dev-режиме предварительное кеширование Angular-входа отключено, чтобы сервер
видел новую сборку библиотеки. Изменения исходников объединяются перед сборкой;
пересборки зависимостей выполняются последовательно.

Главная: `/`; темы: `/foundations/typography` и другие адреса из
`src/app/navigation.ts`; каталог: `/components`; компонент: `/components/icon`.
Разделы статьи открываются обычными якорями, например
`/foundations/typography#fonts`. Query-параметры `theme`, `appearance`, `density`
сохраняют настройки демонстраций в ссылке. Документация остаётся DEFAULT/light/cozy.
Повторный клик по тому же якорю также прокручивает к разделу, даже если URL
не изменился. Структура меню определяется полями `id`, `section` и `level`
в `navigation.ts`, а не сравнением видимых русских названий.
Все страницы подключены без ленивой загрузки. Dev-сервер поддерживает
прямое открытие маршрутов. При размещении production-сборки сервер должен
возвращать `index.html` для маршрутов приложения. Для размещения в подпапке
нужно задать её путь через `--base-href` при сборке. Настройка нового сайта
для GitHub Pages будет выполнена на этапе переключения публикации.
GitHub Pages сам по себе не предоставляет универсальный SPA fallback.
Проверка сайта в подпапке не означает, что прямые ссылки на Pages уже настроены.

Production-сборка: `documentation-site/dist/browser/`. Для просмотра её
нужно раздавать HTTP-сервером; открытие `index.html` через `file://` не предусмотрено.
Результат расположен вне корневого `dist/`, чтобы существующая упаковка
библиотеки не включала сайт. Папка `dist/` уже исключена из Git.

Существующие `npm run dev`, `npm run build`, сборка пакета и GitHub Pages
пока используют прежнюю реализацию. Новые команды не запускают эти сборки.

## Проверка нового сайта

`npm run verify` включает форматирование, сборку и браузерную проверку нового сайта.
В CI они выполняются в существующей группе `catalogue`, после проверок старого
каталога. Отдельно эти шаги можно запустить из корня:

```sh
npm run format:site:check
node documentation-site/tools/run.mjs build --base-href /site-check/ --output-path ../.tmp/documentation-site-check
node documentation-site/tests/smoke.mjs
```

Нужен Chromium из Playwright (`npx playwright install chromium`). Для локальной
проверки установленным Chrome можно задать `PLAYWRIGHT_CHANNEL=chrome`
(в PowerShell: `$env:PLAYWRIGHT_CHANNEL = 'chrome'`). По умолчанию CI использует
Chromium. Проверка запускает временный HTTP-сервер и закрывает его по завершении.

Проверяются загрузка ресурсов из подпапки, прямые маршруты и якоря, публичная
иконка и шрифт, четыре режима, автоматическое оглавление, поиск, мобильное меню
и доступность. Сервер проверки эмулирует SPA fallback, а не правила GitHub Pages.
