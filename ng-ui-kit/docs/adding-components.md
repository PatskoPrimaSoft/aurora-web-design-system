# Добавление компонентов в Angular UI kit

Новый компонент разрабатывается в `ng-ui-kit/` и поставляется из
`@primasoftllc/design-system/angular`. Этот порядок дополняет
[правила Angular UI kit](development.md). Для подключения библиотеки в приложение
используйте [руководство подключения](../../design-system/docs/usage.md).

## 1. Согласуйте назначение и Angular API

Найдите карточку компонента в дизайн-системе: правила применения, состояния,
токены и поведение. Зафиксируйте, какие inputs, события, содержимое и доступное
имя нужны Angular-компоненту. React API и React-превью служат референсом,
но не подтверждают готовность Angular-реализации.

Для кнопки ориентируйтесь на [DsButtonComponent](../src/components/button/README.md).
Если компоненту не хватает общего токена или правила, сначала исправьте основу
в дизайн-системе. Отдельные Angular-цвета и копии палитры не добавляются.

## 2. Создайте компонент в ng-ui-kit

Реализация и её документация находятся рядом:

```text
ng-ui-kit/src/components/<name>/
  <name>.component.ts
  README.md
```

Используйте Angular 19.2, standalone, `ChangeDetectionStrategy.OnPush` и строгие
типы. Для нативного контрола выбирайте атрибутный селектор с ограничением по
тегу, как `button[dsButton]`. Для составного виджета подходит `ds-<name>`.

Следующий пример — только каркас составного компонента. `DsExampleComponent`
и `ds-example` — условные имена, их пока нет в библиотеке:

```ts
import {ChangeDetectionStrategy, Component} from '@angular/core';

@Component({
  selector: 'ds-example',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `<ng-content />`,
  styles: [`
    :host {
      display: block;
      color: var(--ds-fg);
      font: var(--ds-type-body);
    }
  `],
})
export class DsExampleComponent {}
```

Добавьте реальную разметку и поведение по контракту выбранного компонента.
Не имитируйте обычную кнопку через `div` с ручной обработкой клавиатуры.

## 3. Реализуйте состояния и формы

- Inputs объявляйте через `input()`, булевы атрибуты — с `booleanAttribute`.
  Собственные события — через типизированный `output<T>()` без префикса `on`.
  Это правило относится к Angular API. В React-примерах каталога `onClick` и
  `onChange` — свойства с функциями-обработчиками; их имена не переносятся
  в Angular API. Например, React-кнопка использует `onClick={save}`, а
  Angular-кнопка — нативное `(click)="save()"`. Собственное Angular-событие
  объявляется, например, как `readonly selectionChange = output<string>()`,
  отправляется через `selectionChange.emit(value)` и обрабатывается в шаблоне
  как `(selectionChange)="handleSelection($event)"`. Этот пример условный,
  он не описывает API уже выпущенного компонента. Общими для React и Angular
  остаются поведение, состояния и оформление.
- Сохраняйте нативные HTML-атрибуты и события. Не создавайте output `click`
  или `onClick` поверх обычного `(click)`.
- Используйте семантические CSS-токены, размеры в px и отступы родителя.
  Тема, оформление и плотность наследуются через переменные и `auroraScope`.
- Реализуйте применимые состояния: hover, pressed, focus, disabled, loading,
  ошибки и длинный текст. Доступное имя остаётся на интерактивном элементе.
- Для полей значений добавьте ControlValueAccessor и проверьте value, touched,
  disabled и reset в Angular Forms. Кнопке CVA не нужен.
- Освобождайте обработчики и наблюдатели при уничтожении компонента.

Базовый вход не должен импортировать React, ECharts или код приложения.
Графики подключаются отдельно через `/angular/echarts`.

## 4. Откройте публичный экспорт

Добавьте экспорт в `ng-ui-kit/src/core.ts`. Для условного примера выше:

```ts
export * from './components/example/example.component';
```

Экспортируйте также необходимые приложению типы inputs и событий.
Потребитель должен получать компонент из `/angular`, без глубоких импортов
и алиасов `tsconfig.paths` на исходники библиотеки.

## 5. Добавьте документацию и работающий пример

В `README.md` рядом с компонентом опишите импорт, standalone `imports`,
типичный шаблон, inputs, события, значения по умолчанию и ограничения.
Свяжите Angular-документацию с карточкой дизайн-системы.

Добавьте пример в независимые потребители Angular 19 и 20:
`ng-ui-kit/tests/consumers/angular-19/` и `angular-base/`.
Он должен импортировать компонент из установленного пакета, а не из репозитория.
Включите его в отображаемый Angular-шаблон и проверьте реальное поведение
в `ng-ui-kit/tests/browser/`.

Общие примеры можно хранить в `ng-ui-kit/tests/consumers/shared/`.
Если добавляете новый общий файл, включите его копирование в
`ng-ui-kit/tools/check-angular.mjs`: сейчас список этих файлов задан явно.
В этом же инструменте подключаются проверки поведения потребителей;
появление нового файла само по себе не добавляет его сценарии в проверку.

Не подменяйте Angular-пример React-превью или таблицей React props.
Генератор API каталога пока читает React-контракты; Angular API документируется
и проверяется отдельно.

Проверочные примеры потребителей не заменяют публичные демонстрации сайта.
Демонстрации добавляются в `documentation-site/src/app/` и импортируют компонент
из `@primasoftllc/design-system/angular`, а не из исходников библиотеки.
Команды разработки и проверки описаны в [README сайта](../../documentation-site/README.md).
План перехода — [договорённости](../../docs/plans/angular-ui-kit-vision.md).

## 6. Проверьте путь от исходника до приложения

Команды запускаются из корня репозитория, Node 22 берётся из mise.
Во время разработки используйте целевую проверку:

```bash
mise exec -- npm run build
mise exec -- npm run check:angular
```

`build` готовит библиотеку и пакет в `.tmp/package/`. `check:angular` устанавливает
tarball без сети в независимые приложения и запускает production AOT и браузерные
проверки. До первого запуска подготовьте кеши по
[инструкции UI kit](../README.md#команды). Для локального tarball используйте
`npm run pack`; не копируйте в приложение `src/` или `.tmp/package/` вручную.

Проверьте четыре режима: DEFAULT/light/cozy, DEFAULT/dark/compact,
RED2/light/cozy и RED2/dark/compact. Для каждого важного сценария нужны
ширина 390 px и широкий экран, мышь, клавиатура, фокус и доступность.
Для изменяемых inputs проверяйте обновление после первого рендера.
Для форм — отправку, валидацию и reset, для асинхронных действий — loading
и защиту от повторного запуска.

Перед передачей на ревью запустите полный набор. Он уже включает сборку
и проверку Angular-потребителей; повторять целевые команды перед ним не требуется:

```bash
mise exec -- npm run verify
```

## 7. Подготовьте изменение к выпуску

Компонент готов, когда публичный импорт и типы работают из установленного
tarball, проверки Angular 19/20 проходят, документация соответствует примеру
и полный `verify` не ломает прежние сценарии.

Добавьте запись для потребителя под `[Unreleased]` в `CHANGELOG.md`.
Новый совместимый публичный компонент — MINOR, ломающее изменение — MAJOR
по [политике версий](../../docs/release.md#versioning).
Релиз выполняется общим процессом репозитория; наличие компонента в `develop`
ещё не означает, что он доступен для установки из реестра.
