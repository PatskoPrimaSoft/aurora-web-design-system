# Правила Angular UI kit

[Начало](../README.md) · [Подключение](../../design-system/docs/usage.md) · [Дизайн-правила](../../design-system/docs/design.md)

UI kit разрабатывается в этом репозитории и поставляется как библиотека через
`@primasoftllc/design-system/angular`. Приложения устанавливают пакет и импортируют
готовые компоненты. Общие токены, состояния и правила применения остаются едиными
с дизайн-системой; Angular API описывается отдельно от React API.

Практический порядок работы — [добавление компонентов](adding-components.md).

## Версия и текущая готовность

Библиотека компилируется на **Angular 19.2.25**, Node 22, TypeScript 5.8.3.
Независимые потребители используют Angular 19.2.25 / CLI 19.2.27 и
Angular 20.3.34 / CLI 20.3.40, RxJS 7.8.2 и Zone.js 0.15.1.
Поддержка 19.0/19.1 и других major не подразумевается автоматически: для них нужна
отдельная проверка совместимости. SSR, hydration и zoneless пока не заявлены.

Peer range — `^19.2.25 || >=20.3.34`: поддержка ветки 19.2 добавлена без удаления
прежнего диапазона. Реально проверяются 19.2.25 и 20.3.34, не все будущие major.
Версия 5.1.0 была собрана на Angular 20; описанный переход относится к Unreleased.

В исходниках экспортируются `DsButtonComponent`, `DsIconComponent`, сервис темы,
директива скоупа и отдельная интеграция ECharts. Иконка пока не включена в отдельные
проверки потребителей и публичный каталог. React-компоненты поставляются из корневого входа. Tarball устанавливается
в четыре независимых consumer-приложения: Angular 19 core/button, Angular 20 core/button,
Angular 20 charts и Angular 20 legacy. Проверки графиков и старых импортов сохраняются
на Angular 20; отдельная такая матрица для Angular 19 пока не добавлена.
Для новых версий нельзя ограничиваться расширением peer range: нужна установка
tarball, production AOT и браузерная проверка. Удаление поддерживаемого сценария
требует отдельного решения по совместимости и SemVer.

Версия приложения должна быть не ниже версии компилятора библиотеки.
Матрица Node/TypeScript взята из [таблицы Angular](https://angular.dev/reference/versions),
правило компиляции — из [руководства по библиотекам](https://angular.dev/tools/libraries/creating-libraries).
Angular 19 уже вне upstream LTS; здесь он выбран как версия целевого приложения.

## Расположение и поставка

- Реализации: `ng-ui-kit/src/components/<name>/`; публичные экспорты: `ng-ui-kit/src/core.ts`.
- Standalone-компоненты с `ChangeDetectionStrategy.OnPush`, строгими шаблонами и типами.
- Начиная с Angular 19 компоненты, директивы и pipes standalone по умолчанию;
  избыточный `standalone: true` в реализации и примерах не указывать.
- Библиотека поставляется с partial compilation и сгенерированными декларациями.
  Потребитель не компилирует исходники из репозитория через `tsconfig.paths`.
- Angular остаётся peer dependency. Базовый Angular-вход не импортирует React или ECharts;
  графики остаются в `/angular/echarts`. Не добавлять зависимость от приложения.
- Стили и шрифты подключаются один раз через пакетный `styles.css`, как в руководстве.
  Компонентные стили поставляются вместе с компонентом; установка не требует копирования файлов.
- Текущие публичные имена `provideAurora`, `AuroraThemeService` и `AuroraScopeDirective` сохраняются.

## Имена, inputs и outputs

Классы компонентов — `Ds<Name>Component`, директив — `Ds<Name>Directive`.
Для нативного элемента используется атрибутный селектор с ограничением по тегу:
первая кнопка — `DsButtonComponent`, селектор `button[dsButton]`.
Для составного виджета без подходящего нативного корня — `ds-<name>`.
Не создавать универсальный элемент с ручной имитацией клавиатуры обычной кнопки.

Inputs объявляются через стабильный Angular 19 `input()`; имена визуальных параметров
и значения (`tone`, `size`, `loading`) совпадают с эталоном, если не противоречат HTML.
Булевы атрибуты используют `booleanAttribute`. Обязательные значения и значения
по умолчанию явно отражаются в документации. Не переносить ReactNode и React events
в публичные Angular-типы.

Текст и произвольное содержимое передаются через `ng-content`; именованные области
нужны только при отдельном сценарии. Доступное имя остаётся на интерактивном элементе.
Нативные `type`, `name`, `value`, `aria-*`, `data-*` и событие `(click)` сохраняют
обычный смысл. Не добавлять output `click` или дублирующий `onClick`.
Для собственных событий — `output<T>()` с типизированным значением, без префикса `on`.

Компоненты ввода значений поддерживают Angular Forms через ControlValueAccessor:
значение, touched, disabled и reset проверяются в форме. Для кнопки CVA не нужен.
Тексты интерфейса передаёт приложение; внутренние служебные строки должны иметь
типизированный способ переопределения до выпуска соответствующего компонента.
React-провайдеры локализации не являются Angular API.

## Дизайн и поведение

Цвета берутся из семантических токенов, размеры задаются в px, внешние отступы —
родителем. Компонент наследует тему, оформление и плотность через CSS-переменные
и `auroraScope`; не читает глобальную тему для вычисления inline-цветов.
Локальный скоуп имеет тот же приоритет, что в эталоне.

Все состояния из карточки сохраняются: наведение, нажатие, клавиатурный фокус,
disabled, loading и ошибки там, где они применимы. Видимый фокус, контраст,
область нажатия, длинные подписи и reduced motion подчиняются основам системы.
DOM-доступ остаётся локальным, обработчики и наблюдатели освобождаются при уничтожении.

## Первый компонент: кнопка

Доступна [кнопка DsButtonComponent](../src/components/button/README.md):

```html
<button dsButton tone="primary" type="submit" [loading]="saving()">
  Сохранить
</button>
```

Импорт в standalone-компоненте приложения — `DsButtonComponent` из `/angular`.
Сохраняются семь тонов эталона, размеры sm/md/lg, fullWidth, иконки слева/справа,
disabled и loading. Тип по умолчанию — `button`; `submit` задаётся явно.
Loading сохраняет размер, подпись и фокус, выставляет aria-busy/aria-disabled и
блокирует повторные действия и отправку формы. Disabled использует нативную блокировку.
Проверяется также обработчик `(click)` самого приложения: одной смены оформления
или aria-атрибута для блокировки недостаточно.

## Документация и критерии готовности

Правила применения, токены и сценарии живут в существующей карточке компонента.
React `.d.ts` описывает React API; Angular-декларации генерируются из Angular-кода.
Существующий генератор API каталога пока читает React: нельзя показывать его таблицу
как Angular API или React-превью как доказательство Angular-поведения.

Пока Angular API документируется рядом с исходником, а работающие проверочные примеры
находятся в независимых Angular consumer-приложениях. Руководство подключения ссылается
на документацию компонентов. Эти приложения проверяют поставку пакета и не являются
публичным каталогом.

Публичные демонстрации будут размещаться в отдельном приложении сайта и не войдут
в библиотеку. Согласованный план хранится в репозитории в
`docs/plans/angular-ui-kit-vision.md`; устройство подключения нового сайта ещё обсуждается.

Компонент готов к поставке, когда:

- экспорт и типы доступны из установленного tarball без source aliases;
- production AOT проходит в целевом Angular 19.2 и в сохраняемом Angular 20 consumer;
- реальные браузерные тесты проверяют мышь, клавиатуру, фокус, формы и изменения inputs;
- проверены DEFAULT/light/cozy, DEFAULT/dark/compact, RED2/light/cozy,
  RED2/dark/compact, ширина 390 px и широкий экран, длинный текст и доступность;
- пример подключения компилируется, API и ограничения описаны, CHANGELOG обновлён;
- полный `npm run verify` проходит, включая прежние React и Angular проверки.

Новый компонент переносится после проверки первого полного пути «исходник → пакет →
приложение». Отсутствующий токен или общее правило исправляется в дизайн-системе,
без отдельной Angular-палитры и расходящихся копий основ.
