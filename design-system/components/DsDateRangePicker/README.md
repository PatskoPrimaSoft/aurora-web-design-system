## Правила применения

- Для периода используйте связанную пару полей с понятным заголовком: «Период отчёта», «Ночная смена». Группа оформляется через `fieldset`/`legend`; подписи каждой границы связаны с input.
- `granularity="date"` принимает календарные даты `YYYY-MM-DD`, `granularity="datetime"` — местные дату и время `YYYY-MM-DDTHH:mm`. Внутри используются нативные input; их календарь, формат отображения и клавиши задаются браузером и системой.
- Передайте `timeZone`: это видимое пояснение, связанное с обоими полями. Компонент не пересчитывает значения между часовыми поясами, не конвертирует их в UTC и не определяет неоднозначное время при сезонном переводе часов. Это ответственность приложения.
- `presets` содержит готовые границы, вычисленные приложением в его часовом поясе. «Сегодня» — календарный день этого пояса; «вчера» вычисляйте календарным сдвигом, а не вычитанием 24 часов из момента времени. Пример фиксирует опорную дату, чтобы результат был воспроизводимым.
- Начальная граница должна быть не позже конечной; равные границы разрешены. Обратный порядок сразу показывает ошибку у конца периода и блокирует нативную отправку формы. Пустые границы допустимы, пока не задан `required`; он требует оба значения.
- `min`, `max` и `step` применяются к обоим полям, включая ввод с клавиатуры. Границы включительные; шаг — дни для date, секунды для datetime. Сообщения Aurora переводятся через `DsStringsProvider`.
- Период не добавляет скрытого конца дня `23:59:59`. В примерах календарного отчёта обе даты включительны; правила запроса и перевод в полуоткрытый интервал задаёт приложение.
- `name="report"` создаёт `report.from` и `report.to` в FormData; для других имён есть `fromName` и `toName`. `form` связывает оба поля с внешней формой. `error` приложения показывается у конечной границы и блокирует отправку; очищает её приложение.
- Используйте `value` и `onChange` для управляемого периода либо `defaultValue` для неуправляемого. Сброс формы восстанавливает неуправляемые границы. Для управляемых границ сбрасывайте состояние в `onReset`.
- `disabled` исключает поля из Tab и FormData. `readOnly` сохраняет фокус и FormData. В обоих состояниях готовые периоды неактивны. Tab проходит по границам и кнопкам; Enter/Space активируют доступную кнопку. `ref` указывает на fieldset.

## Пример кода

Управляемые календарные границы отчёта; значения сохраняются без преобразования часового пояса.

```jsx
import { useState } from 'react';
import { DsDateRangePicker } from '@primasoftllc/design-system';

export function Example() {
  const [period, setPeriod] = useState({from:'2026-10-12',to:'2026-10-19'});
  return <div style={{display:'flex',flexDirection:'column',gap:16}}>
    <DsDateRangePicker label="Период отчёта" value={period} onChange={setPeriod}
      fromLabel="Первый день" toLabel="Последний день" timeZone="Europe/Minsk"/>
    <output aria-live="polite">{period.from || '…'} — {period.to || '…'}</output>
  </div>;
}
```
