Адаптивность в интерфейсе

На узком экране содержимое располагается последовательно, на широком список можно поставить рядом со сведениями. Дизайн-система задаёт общие пороги ширины — брейкпоинты. Приложение определяет, что меняется при переходе между ними.

Переключите компоновку и выберите объект: сведения и действие остаются доступны в обоих вариантах.

Это демонстрация вариантов, а не измеритель ширины окна. Узкий вариант ограничен 390 px. Если места мало, две колонки также складываются в одну.

Краткая памятка

Диапазоны описывают ширину окна. Ниже — возможные решения: переход через порог не требует перестройки, если текущая компоновка удобна.

S · 360–719 px
Начните с одной колонки: главное содержимое и основные действия идут последовательно.
M · 720–959 px
Список и сведения могут оставаться друг под другом. Используйте ширину для более длинных подписей.
L · 960–1139 px
Можно разместить список и сведения рядом, сохранив удобную ширину основного содержимого.
XL · от 1140 px
Используйте дополнительное пространство для данных; длинные абзацы ограничивайте по ширине.

В памятке S показан от минимальной поддерживаемой ширины. Технически он включает любую ширину меньше 720 px.

На какой ширине проверять

Для наших макетов используем контрольные ширины окна в CSS px. Это набор проверок, а не дополнительные брейкпоинты или разрешения мониторов.

  • 1440 CSS px — основной десктопный макет: навигация, рабочая область и нужные боковые панели.
  • 1280 CSS px — более тесное окно: проверьте место для содержимого с открытой навигацией.
  • 1920 CSS px — широкое окно: проверьте, что данные используют пространство, а текст и формы не растягиваются.
  • 360 CSS px — минимум основной компоновки.
  • 390 CSS px — основной мобильный макет.
  • 320 CSS px — проверка доступности при узком окне и увеличении страницы. Сохраняйте данные и действия; допустима одна колонка.

Компоновка на десктопе

Ориентируйтесь на место, оставшееся для задачи после навигации и панелей. Даже на большом мониторе окно может занимать половину экрана.

Список и сведения
Расположите рядом, если оба блока остаются удобными. При сужении окна перенесите сведения под список или открывайте их отдельно, сохраняя выбор и путь назад.
Боковые панели
Оставляйте рядом с рабочей областью, пока они не мешают основной задаче. При нехватке места сворачивайте их с доступной кнопкой открытия.
Текст и формы
Ограничивайте ширину контейнера и длину строк. Свободное место по краям допустимо; поля не нужно растягивать на весь монитор.
Таблицы и карта
Отдавайте им оставшееся пространство. У таблицы сохраняйте читаемые колонки и собственную горизонтальную прокрутку, если данные не помещаются.

Правила адаптации

  • Сохраняйте доступ к действиям. Если кнопка переносится в меню, оно должно работать с клавиатуры и на сенсорном экране.
  • Сохраняйте контекст. При перестройке не сбрасывайте выбранный объект, введённый текст и состояние формы. Порядок чтения и перехода по Tab должен оставаться понятным.
  • Проверяйте содержимое. Длинные названия и подписи должны переноситься или раскрываться. Не уменьшайте шрифт и не скрывайте важные данные ради одной строки.
  • Разделяйте ширину и плотность. Узкий экран сам по себе не включает компактный режим. Выбирайте плотность с учётом удобства управления.
Чек-лист проверки
  • Проверьте компоновку на размерах из памятки выше. На десктопе откройте боковые панели и сузьте окно до половины экрана: основные данные и действия должны остаться доступны.
  • Сравните соседние ширины: 719/720, 959/960 и 1139/1140 px. Контролы не должны обрезаться или перекрывать друг друга.
  • Перестройте интерфейс после выбора объекта или заполнения формы: состояние должно сохраниться.
  • Пройдите по действиям клавишей Tab и проверьте длинные подписи.
  • У страницы нет горизонтальной прокрутки. Широкая таблица может прокручиваться внутри своей области.

Для собственной разметки

Для компоновки страницы используйте ширину окна, для блока внутри панели — ширину его контейнера.

Ширина в CSS-пикселях

Проверяйте доступную ширину окна в CSS px, а не физическое разрешение экрана. В WCAG Reflow 320 CSS px соответствуют, например, окну 1280 px при увеличении до 400%. Это проверка доступности, которая дополняет основной минимум 360 px.

Пороги и ширина содержимого
ТокенЗначение и назначение
--ds-bp-m720 px · начало M.
--ds-bp-l960 px · начало L.
--ds-bp-xl1140 px · начало XL.
--ds-bp-s-max, --ds-bp-m-max, --ds-bp-l-max719, 959 и 1139 px · верхние границы для целых px.
--ds-content-max1440 px · ограничение ширины форм и текстовых страниц.
--ds-content-max-prose72ch · ограничение длины строки абзаца.

Ширина окна и ширина блока

Media queries проверяют ширину окна. Для локальной адаптации задайте родителю container-type: inline-size и используйте @container: карточка внутри узкой панели сможет перестроиться даже на широком экране. Порог выбирайте по содержимому блока.

Пороги в CSS

CSS-переменные нельзя подставлять в условие media query через var(). В примере используется числовой порог 960px, соответствующий --ds-bp-l. Правила без media query задают узкую компоновку, min-width включает широкую с указанного порога.

Ограничение ширины

Применяйте max-width: var(--ds-content-max) к контейнеру формы, max-width: var(--ds-content-max-prose) — к абзацам. Карта и таблицы могут занимать доступную ширину. Ограничение не требует отдельного переключения на XL.
