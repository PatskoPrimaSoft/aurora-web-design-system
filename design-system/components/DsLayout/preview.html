Карта занимает свободное место

В рабочем экране панель помогает выбрать объект, а карта использует оставшуюся ширину. Выберите объект в списке или на схеме: обе области показывают один выбор.

Ширина панели определяется её задачей, а не долей экрана. Основной регион может растягиваться. Готовый DsPageLayout размещает регионы; приложение выбирает их состав и наполнение. В примере выше каркас задан собственной CSS-сеткой.

Выбирайте компоновку по задаче

  • Карта и рабочая область: вспомогательная панель имеет ограниченную ширину, основной регион получает остаток.
  • Таблица: использует доступную ширину. Поиск, фильтры и результат имеют общую левую границу.
  • Форма: ограничена удобной для чтения шириной. Связанные короткие поля могут стоять рядом; длинные занимают всю строку.

Не вводите обязательную сетку из 12 колонок для каждого экрана. Число колонок следует содержимому. Расстояния задаются по правилам отступов и группировки, перестроение при нехватке места — по правилам адаптивности.

Каркас приложения и сетка содержимого

Каркас задаёт внешние регионы: шапку, навигацию, боковые панели и основной регион. Сетка выравнивает контейнеры уже внутри основного региона. Её колонки не проходят через навигацию и боковую панель.

Включите направляющие: карточки занимают колонки внутренней сетки. Кнопки внутри контейнера располагаются по содержимому и отступам; иконки и всплывающие меню также не нужно подгонять под колонки страницы. Четыре колонки здесь служат наглядной схемой, а не обязательным стандартом Aurora.

Ограниченная и растягиваемая ширина

Сравните два способа распределения места в одной области. Переключите содержимое между формой и картой, затем измените ограничение ширины. На узком экране оба варианта занимают доступное место.

Для формы ограничение помогает сохранить связь подписи, поля и действия. Карте полезно отдавать свободное место для обзора. В этом примере предел формы — 560 px: это решение сценария, а не универсальная ширина всех форм или новый токен.

Таблица и фильтры образуют одну область

Фильтры находятся над результатом, а не в независимой колонке без связи с таблицей. Поиск и переключатель в примере меняют строки. При нехватке ширины прокручивается только таблица: фильтры остаются доступны.

Не сжимайте столбцы до нечитаемого текста ради размещения всех данных. Состав колонок выбирает приложение. Порядок строк описан отдельно в правилах сортировки.

Форма сохраняет удобную ширину

Форма не обязана растягиваться вслед за окном. Название занимает всю строку; два связанных значения стоят рядом. Подписи находятся над полями, а кнопки начинаются на той же левой границе.

Внешнюю ширину и расположение полей задаёт родитель. Готовые поля и кнопки сами оформляют содержимое и состояния. Проверяйте порядок Tab: он должен совпадать с порядком чтения.

Назначьте владельца прокрутки

  • Для обычной страницы оставляйте одну вертикальную прокрутку документа. Длинная форма продолжается вниз, без собственного окна прокрутки.
  • В рабочем экране с картой приложение может ограничить высоту каркаса и дать списку собственную прокрутку. Карта остаётся на месте; не добавляйте прокрутку всем вложенным панелям.
  • Горизонтальную прокрутку локализуйте внутри широкой таблицы или кода. Область должна быть доступна с клавиатуры и иметь понятное имя.

У DsPageLayout есть режимы scroll="page" и scroll="regions"; для них родитель задаёт высоту. Обычному потоку подходит scroll="none". Контракт — на странице компонента.

Для собственной разметки

Каркас распределяет место между регионами, внутренняя сетка выравнивает контейнеры. Компоненты управляют своим оформлением. Не меняйте размер текста или внутренние размеры контролов, чтобы исправить тесную компоновку.

Как не дать содержимому растянуть страницу
  • minmax(0, 1fr) позволяет основному столбцу уменьшаться ниже ширины длинного содержимого.
  • min-width: 0 на дочернем регионе разрешает ему сжиматься внутри grid или flex.
  • max-width ограничивает форму; числовые размеры примеров — решения для этих сценариев, а не новые системные токены.
  • Для панели внутри другого региона учитывайте её собственную ширину. Порог перестроения и container queries описаны в адаптивности.
