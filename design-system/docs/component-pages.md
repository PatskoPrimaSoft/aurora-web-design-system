# Стандарт страницы компонента

Эталон — [DsCheckbox](../components/DsCheckbox/preview.html). Используйте этот
шаблон при создании и переработке страниц компонентов. Основы, бренд, карта,
миграционные документы и эталонные экраны сохраняют собственную структуру.

## Порядок блоков

| Блок | Содержимое | Источник |
| --- | --- | --- |
| Название и назначение | Публичное имя компонента и одна короткая фраза о его задаче | `@dsCard`: имя и `subtitle` |
| Живые примеры | Обычное использование, отдельные сценарии и варианты, затем общая матрица состояний при необходимости | `preview.html` |
| Правила применения | Ограничения и важные особенности поведения, включая клавиатуру | `README.md` |
| Пример кода | Один короткий рабочий пример типичного подключения | `README.md` |
| Параметры | Имя, тип, значение по умолчанию и описание; обязательность рядом с именем | Реализация и `.d.ts`, генерируются автоматически |
| Токены | Токен и его роль именно в этом компоненте | `API.md` |

Пустые блоки не добавляются. Особенности компонента помещаются внутрь этих
блоков: не создавайте отдельные разделы верхнего уровня «API», «Состояния» или
«Доступность», повторяющие уже показанное. Для независимых примеров допустимы
подзаголовки третьего уровня внутри живых примеров.

## Подключение шаблона

В `design-system/components/<Name>/preview.html` добавьте `layout="component"` к `@dsCard`.
Остальные метаданные — группа, aliases, высота и subtitle — сохраняются.

```html
<!-- @dsCard layout="component" group="5 · Компоненты · формы" height=560 subtitle="Выбор нескольких элементов или одного варианта из группы" -->
```

Общий каталог выводит заголовок «Живые примеры», описание и API на основной
странице, скрывает отдельные ссылки на описание/API и подстраивает iframe под
ширину и высоту содержимого. Не добавляйте имя компонента и заголовок «Живые
примеры» повторно внутрь превью.

`README.md` содержит только `## Правила применения` и `## Пример кода` — те
блоки, которые нужны компоненту. Назначение уже указано в subtitle. Не копируйте
таблицу параметров из `.d.ts` в Markdown.

`API.md` при необходимости содержит `## Токены` и таблицу «Токен / За что
отвечает». Здесь описывается применение токена, а не его значение в каждой теме:
значения и общие определения принадлежат общему справочнику токенов.

Для компонента, запланированного к замене, добавьте `status="deprecated"` в `@dsCard`: каталог покажет DsLozenge «Устарело» рядом с названием в меню и шапке. Причину и план замены кратко укажите в subtitle.

## Общий шаблон живых примеров

Внутри превью используйте `LiveExamples` для набора и `LiveExample` для каждого
сценария. Сборщик подключает их из `design-system/catalog/live-examples.jsx`, если у `body` есть
атрибут `data-ds-examples`; общие стили находятся в `design-system/catalog/live-examples.css`.
`LiveExamples` отслеживает тему один раз на весь набор и оставляет пояснения на
белой поверхности. `LiveExample` добавляет заголовок, копирование ссылки, область
демонстрации и раскрываемый код.

```html
<body data-ds-examples>
  <div id="root"></div>
  <script type="application/json" id="example-code-sources"
    data-ds-example-sources="examples.json"></script>
  <script type="text/babel">
    const { LiveExamples, LiveExample } = window.DsLiveExamples;
    const { DsButton } = window.AuroraWebDesignSystem_96e210;

    ReactDOM.createRoot(document.getElementById('root')).render(
      <LiveExamples>
        <LiveExample id="create-task" title="Создание задачи"
          description="Основное действие на странице задач.">
          <DsButton>Создать задачу</DsButton>
        </LiveExample>
      </LiveExamples>
    );
  </script>
</body>
```

`id` — уникальный стабильный якорь и ключ в `examples.json`; `title` — название
сценария; `description` — необязательное пояснение; `children` — живая демонстрация.
Код берётся автоматически из `examples.json` по `id`. Если кода нет, переключатель
не показывается; если в наборе вообще нет сниппетов, скрипт с JSON можно опустить.
Не передавайте тему вручную и не копируйте стили, обработчики ссылок и буфера обмена
на страницу компонента. В `preview.html` остаются только сценарии и их собственная
разметка; подключение пакета и код сценариев хранятся в `examples.json`.

## Содержание без повторов

Заголовки и пояснения пишутся по-русски; имена компонентов, параметров и типов
сохраняются как в публичном API.

- Матрица показывает состояния. Не сопровождайте её второй текстовой таблицей
  «unchecked — не выбран / checked — выбран».
- Правила объясняют то, чего не видно из примера: переход из частичного выбора,
  обязательное доступное имя, связь с родительским состоянием, клавиатуру.
- Пример кода содержит необходимые импорты, начальное состояние и обработчик,
  если компонент управляемый. Он должен работать после подключения пакета и его
  общих стилей. Не добавляйте сразу несколько одинаковых способов использования.
- Описания параметров объясняют их назначение и существенные ограничения. Тип
  и default берутся из исходников; не повторяйте их словами без необходимости.
- Не включайте историю реализации, пути файлов и технические комментарии в
  основной текст. Нужные ссылки на исходники можно разместить компактно внизу.

## Оформление и прокрутка

- Оболочка каталога остаётся DEFAULT/light/cozy с белой поверхностью `ds-surface`.
  Бренд, оформление и плотность переключаются в шапке каталога;
  настройки применяются к превью и сохраняются в ссылках, не меняя оформление документации.
- Название компонента — 32 px, заголовки разделов — 24 px, основной текст — 16 px.
  Между разделами — 48 px (32 px на узком экране). Таблицы разделяются горизонтальными
  линиями; цвет и шрифт берутся из токенов Aurora.
- Начинайте живые примеры с обычного интерактивного использования, затем показывайте
  отдельные сценарии и варианты. Общая матрица состояний при необходимости завершает
  набор. Эталон — `DsCheckbox`.
- Каждый независимый пример оформляйте отдельной секцией: заголовок третьего уровня
  с названием сценария → короткое описание, объясняющее применение или поведение →
  интерактивная демонстрация в собственной области с тонкой рамкой. Общая матрица
  состояний может завершать набор, но не заменяет отдельные сценарии.
- Заголовки и описания примеров остаются на белой поверхности DEFAULT/light/cozy;
  выбранные бренд, оформление и плотность применяются только к демонстрациям.
  Эталон `DsCheckbox` использует `body[data-ds-examples]`, `scopeMode="inherit"`
  и области `[data-ds-example-demo]`. Каталог убирает внешнюю рамку вокруг набора,
  а превью синхронизирует тему демонстраций с атрибутами своего корневого `html`.
- Оглавление формируется из «Живых примеров» и существующих заголовков второго уровня.
  Заголовки `h3[id]` внутри `body[data-ds-examples]` автоматически добавляются вложенными
  пунктами к «Живым примерам». Идентификаторы должны быть уникальными и стабильными.
  На экранах от 1400 px оно закреплено справа, на узких — раскрывается под назначением
  компонента. Ссылки сохраняют карточку, настройки примера и якорь раздела; активный
  пункт следует за прокруткой. Переход с клавиатуры переводит фокус на заголовок.
  Возле заголовка примера предусмотрена кнопка копирования ссылки с текущими брендом,
  темой, плотностью и якорем. Результат объявляется через `role="status"`; при отказе буфера
  обмена доступно выделенное поле со ссылкой для ручного копирования.
- Для блоков кода указывайте язык Markdown-ограждения (`jsx`, `tsx`, `html`, `css` и т. п.).
  Под каждым живым примером размещайте закрытый по умолчанию блок «Показать код».
  Сниппет включает импорты и необходимое состояние React для конкретного сценария.
  В `DsCheckbox` исходники хранятся в `examples.json` по идентификаторам заголовков;
  `script#example-code-sources[data-ds-example-sources]` загружает и подсвечивает их
  при сборке. Копирование и стили блока общие с документацией.
  Подсветка генерируется при сборке; неизвестный язык остаётся обычным текстом.
  Кнопка «Копировать» сохраняет текст и отступы, объявляет результат; при недоступном
  буфере обмена код выделяется для ручного копирования. Широкий код прокручивается
  внутри блока и доступен с клавиатуры.
- Одна колонка, общая левая граница и максимальная ширина 920 px для превью и
  документации.
- Типографика, расстояния между разделами и таблицы задаются в
  `design-system/catalog/styles.css`. Не копируйте оформление страницы в каждый README.
- Область демонстрации использует `ds-surface` и существующие токены компонента;
  тонкая рамка отделяет её от заголовка и описания. Внешние отступы принадлежат
  примеру, а не компоненту.
- Превью строится обычным потоком и адаптируется по ширине. Не задавайте ему
  `100vh`, фиксированную высоту body или внутреннюю вертикальную прокрутку.
  Метаданные высоты служат исходным размером до измерения содержимого.
- Для диалогов, меню и всплывающих слоёв выделяйте демонстрационную область
  обычным потоком: её размер должен учитывать показанный слой, даже если сам
  слой использует абсолютное или фиксированное позиционирование.
- Страница прокручивается вертикально целиком. Горизонтальная прокрутка
  допустима для широкой таблицы или кода, но не для всей страницы и не для
  стандартного превью компонента.

## Проверка переработанной страницы

Проверьте порядок блоков, отсутствие повторов и отдельных переходов за
описанием/API. Просмотрите страницу на ширине 390 px и на широком экране. Превью не должно обрезать содержимое или
создавать вторую вертикальную прокрутку.

Проверьте DEFAULT/light/cozy, DEFAULT/dark/compact, RED2/light/cozy,
RED2/dark/compact и клавиатурное управление живыми примерами. Изменения
параметров должны автоматически отражаться в таблице после сборки. Общий
браузерный контракт страницы проверяет `tests/browser/component-page.spec.js`.
